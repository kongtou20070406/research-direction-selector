# RDS 6.1：插件里的指南针

状态：路线已在本地提交 `79e2fe5`。发布说明和 Luna 判读规则随后提交。标签未打，分支 `NOT_PUSHED`。写于 2026-10-29。从 `release/6.0.0-compass` 做起，不改 `main`。

## 目标

RDS 仍是宿主读的 Skill / 插件，不变成科研工具本身。工具和 MCP 留在外层，限制少：模型可以自由调用它们做开放科研。内核只做两件事：记下会改变下一步的那几条事实，并在每一轮把模型拉回这些事实。

增效来自指南针，不来自多一套执行器。模型看到的不是账本、旧对话或语法树，而是一张不超过 4096 字节的卡：目标、冻结的判据、已经试过什么、哪条证据相冲突、下一个该问的问题。模型先回答这张卡，再去用外层工具。

成功标准：

- 普通科研只走一条路线：读卡，回答指南针，外层工具去做，把结果记回来。
- 卡不超过 4096 字节，不含假说 AST、原始 stdout、旧对话、语法。
- 记录不启动科研工具，也不在内核里调模型。相同命令再次登记时复用旧回执，不新跑。
- `status` 和 `fold` 不启子进程。命令假说不进重放循环。
- 现有 `IDENTIFY_LAW` 回归仍绿。
- 发布说明写明：不证明科学发现，不证明比裸模型更准。Luna 没有真实用量就写 `UNKNOWN`，不写 0。

## 保留与推翻

保留一本账：`ProjectStore` 事件、CAS、回执字节绑定、fail-closed、`INPUT_REPORTED` 不等于科学支持。`scientific_support` 仍恒为 `UNKNOWN`。不新建数据库、表或线程。

推翻的是默认产品，不是账本。普通科研不再走语法合成、EIG 选点、盆地逃逸、RSI。这些留给显式的旧声明，默认技能不加载。F2 的网格加密仍不可购买。F5 的预算表分列不做。

不从零写第二个内核。“从头”指的是产品行为：一条新的技能路线加一个小记录器，旧的发现循环降为可选。

## 数据流

```text
宿主加载 Skill
  -> compass status 只读一张卡
  -> 模型先用普通话回答：判断、下一步、什么观察会改变判断
  -> 模型自由使用外层工具 / MCP
  -> 只把关键结果记回来：判据哈希、试验身份、指标、回执哈希、是否改了口径
  -> 下一轮再读卡
```

卡字段写死：`schema`、`head`、`goal`（不超过 512 字）、`criterion_sha256`、`tried`（最多 5 条：id、metric、receipt_sha256）、`conflict`（最多 1 条）、`question`、`unknown`（最多 8 条）、`next`、`scientific_support`。

`next` 只能是 `ANSWER`、`RECORD`、`REUSE`、`STOP`。`ANSWER` 是指南针拉模型：卡上有一个具体问题，技能要求先回答再调工具。`RECORD` 表示这一步只差一条记录。`REUSE` 用现有 `execution_route`，命中旧回执就不再跑。缺判据或缺停止规则时是 `STOP`，原因写在卡上，不填默认值。

内核不调模型。“拉”发生在插件：宿主已经在跑模型，技能每轮只把这张卡放进去。额度花在宿主那一次调用上，不再被内核加一次。

## 边界

- 没有容差：不比大小，卡上 `STOP`。
- 非零退出、超时、缺产物：记失败，不当成指标。同一路由失败两次则 `STOP`，原因 `REPEATED_FAILURE`。
- 判据哈希变了计一次口径修改。
- 卡被截断后，模型仍可能自己读仓库。评估测的是按技能做时花多少，不是物理上读不到。
- 内核不禁止外层工具，也不替模型选工具。
