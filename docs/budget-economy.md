# 预算经济：花出去，也赚回来（2026-10-20）

问题：当前 Compass 预算是单向消耗——`budget.experiments` 花完就停，agent 只被约束「省着花」，没有「推进目标换资源」的正向激励。测 EIG 的资源化口径也缺失：所有公开 benchmark 都没有「花钱买测量」的原生机制，成本数字不可比。

## 1. 计费口径（预注册）

在 declaration 里冻结，跑之前写死，跑完不许改。

| 动作 | 计费 |
| --- | --- |
| 一次测量（新输入点） | 1 实验单位 |
| 重复同一测量（已测点） | 2 单位（惩罚浪费） |
| 数据访问（DiscoveryBench） | 按 行 / 列 / 数据集 计费，见适配层 |

## 2. 奖励表（预注册）

| 推进目标的行为 | 返还 |
| --- | --- |
| 发现反例（推翻一个存活假设） | +0.5 |
| 假设空间减半（存活假设数降一半） | +1 |
| holdout 通过 | +2 |
| claim 通过且未被推翻 | +5 |

## 3. 净预算

```
net = min(max_experiments, 初始 experiments − 已花 + 奖励)
```

- 硬上限 `max_experiments` 不变，奖励只在软预算层生效；
- 奖励与花费同口径记账，进 `report.cost`，可审计；
- 每一次奖励返还都绑定 receipt（哪次测量、哪个假设被推翻），不可凭空发放。

## 4. 防作弊（三条，先写死）

1. **奖励规则冻结**：declaration 里写死后，跑中改规则视为作弊，整轮作废；
2. **奖励上限**：单轮奖励 ≤ 已花费 × 2，防止「制造假反例换预算」；
3. **扣回**：claim 被后续证据推翻时，扣回对应奖励（+5 → −5），并记 `CLAIM_RETRACTED`。

## 5. 最小实现

- declaration 加 `budget.rewards`（映射：事件 → 返还量，可缺省）；
- `decide` 在事件发生时把奖励写入 state，`can_buy` 用 `net`；
- `report.cost` 增加 `rewards`, `net_experiments`, `retracted`；
- 测试：不设奖励时行为与现在一致；设奖励时，发现反例后能多买一次实验；奖励超上限时封顶。

## 6. 边界

- 奖励会改变 Pareto 上的成本轴，必须与「无奖励」臂分开报告，不能混；
- 奖励表本身是人为设计，不证明「RDS 更会科研」，只证明「经济激励对齐目标」；
- `scientific_support` 仍为 `UNKNOWN`，奖励不升级 claim。
