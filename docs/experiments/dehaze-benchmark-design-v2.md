# 去雾任务设计 v2（评审后修正）

v1 见 `dehaze-benchmark-design.md`。**v1 的地基被推翻了**，这篇是修正版。

推翻它的是一条事实核查，不是意见：

> **O-HAZE 是公开发布的数据集**（Springer 论文原文 "publicly available"，OpenDataLab 与多个镜像可下载）。
> 所以「不给测试集」不构成 holdout——41–45 的 GT 网上就能下。

第二条同样硬：**只限制「最终 3 小时」而不限制搜索，测的是一支队伍的搜索算力，不是结构设计。**

---

## 1. 定位降级

| v1 的说法 | v2 的说法 |
|---|---|
| 去雾基准 / 排行榜 | **受控研究**：固定总预算下，小样本真实去雾的容量与泛化权衡 |
| 比谁 PSNR 高 | 比较「结构选择」在匹配条件下的差异，且必须能被消融验证 |
| holdout 盲测 | **不是盲测**。除非另找未发布数据，测试侧一律标注为「已知公开数据」 |

**排行榜要砍掉，除非两件事同时补上**：未发布的独立测试数据，以及可审计的累计预算。缺一个，排名就在测搜索资源。

---

## 2. 资源与约束：唯一的公平判据是参数

v1 的漏洞：只限制「最终 3h」而不管搜索，测的是搜索算力。评审建议改成累计 GPU 时。

**定案（终稿）：不限制前向次数，不设累计预算，不按算力评分。唯一的公平约束是
可学习参数 ≤ 50,000。目标：测试集 PSNR 越高越好。**

理由：当计算不受限时，**「用同一组权重跑更多步」是唯一不需要增加参数的增益途径**。
限制计算会把这个信号削掉，而它正是要观察的结构选择。参数是唯一客观、无法被
残差/分组卷积/隐式展开绕过的复杂度度量。

具体：

- 可学习参数 **≤ 50,000**。这是硬约束，超出即无效。
- 前向次数、迭代步数、推理时重复调用：**不限**。
- **目标函数单一**：test-A PSNR 越高越好。不设「省算力」加分，不设复合目标。
- 训练时长 3 小时是**资源配额**（一台机器给 3h），不是比较变量。
- 仍要求报告实际耗时与显存峰值，用于事后分析「用计算换参数」的代价，但不进排名。
- 固定硬件、固定驱动与 CUDA 版本，记录在案。
- 禁止：预训练权重、外部数据。TTA 允许，分数单列。

这样规则只剩一条，队伍没有可钻的空子，而「结构设计」成为唯一变量。

### 2.1 50k 下预期 PSNR 落在哪

identity 基线（直接输出 hazy）在 O-HAZE 上大约 12–14 dB。50k 参数的目标区间大致是
**13–20 dB**——具体要跑基线才知道。这个区间很窄，所以第 4 节的指标口径必须钉死，
否则 0.3 dB 的差异会被口径噪声淹没。

**越高越好这条没有上限目标，意味着它是排名制**（见第 1 节：排行榜要砍）。两者冲突，
所以最终形态是：不公开排名，但公开每队 PSNR 与配对差值区间，谁高谁低读者自己看。

## 3. 参数：100k 保留，但标为待校准

老板定的 0.1M 保留。但评审指出它和 3h 没有对应关系：共享权重反复展开几乎不增参数，而原尺寸特征很贵，所以「100k」对容量可能过紧、对计算可能过松。

- 保留 **≤100,000 可学习参数**。
- 同时记录**实测峰值显存与单图推理时延**，作为计算侧的度量。
- **校准方法**：先用三个基线（identity、单层 3×3、暗通道）跑一次，看 PSNR 是否能区分结构。如果三者挤在 0.5 dB 内，100k 就该放宽。
- 评审建议的替代值是 **250k**（未测速，仅作候选）。这是产品决策，由你定。

---

## 4. 指标口径（必须冻结到像素级）

v1 只写了「sRGB、裁 4px」，不够。评审列出的漏洞：

| 变量 | 冻结规则 |
|---|---|
| 评分分辨率 | **必须在 GT 原尺寸上算**。禁止自行缩到 512 后评分。 |
| 解码 | 指定解码器与版本；记录是否应用 EXIF 旋转。 |
| 色彩 | 统一到 sRGB，禁用 ICC 变换的不一致路径；固定 RGB 范围 [0,255]、float 与 uint8 的转换点。 |
| 量化 | PSNR 在 uint8 上算（先 clip 再 round），写明。 |
| 配准 | **由组织者预先确定并公开**，禁止按预测结果调整对齐。 |
| 有效区域 | 共同有效 mask 预先算好并公开（因为 GT 与 hazy 可能存在轻微错位或黑边）。 |
| SSIM | 指定实现与参数（window、常数），不许换库。 |
| 4px 裁边 | 保留，但**它解决不了错位、曝光差与 JPEG 痕迹**，这三项必须单独报告误差统计。 |

另外：**必须交每图 PSNR 列表**，不接受只有平均值。

## 5. test-B 的归因限制

v1 把 indoor 512 patch 当「分布外测试」。评审指出它同时改变了**场景（indoor）、分辨率（512）、裁取方式（patch）**三个变量，而且多个 patch 可能来自同一张原图，不能当独立样本。

v2 的两种处理：

- **最小补丁（推荐）**：给 test-A 也构造一条 **512 patch 轨道**（同样的裁取与缩放协议），这样「A-512 vs B-512」只差场景，归因干净；而「A-全尺寸 vs A-512」分离分辨率效应。
- **否则**：把结论降级为「联合域偏移」，不许说「跨场景泛化」。

另外：**B 的独立原场景数要报出来**（如果 5 对 patch 来自 3 张原图，有效样本是 3 不是 5）。

---

## 6. 统计口径

5 张 test-A 撑不起点估计的排名。v2 要求：

- 配对差值的 **bootstrap 置信区间**（按图像采样，不是按像素）。
- 多 seed 的方差必须报，且**不得用「多次运行取最好」当结果**。
- 结论只能写成「在 n=5 的配对比较中，差值中位数与区间为 X」，不许写成「A 优于 B」。

---

## 7. 假设 H 的保留与改写

v1 的假设「参数上限会逼出参数复用/循环」保留，但判据要加固：

- 用 `state_dict` 的**独立参数张量数**与**前向调用次数**的比值，不看代码里有没有 for 循环（防止加假循环通过检查）。
- 提交必须附 `state_dict` 键名与形状清单。
- **如果 100k 校准后放宽到 250k，H 需要重新表述**：约束变松，「逼出复用」的驱动力就变弱。

---

## 8. 这份设计现在能支持什么

**能支持**（在补齐上面的规则之后）：

> 在累计 3 GPU 时、≤100k 参数、40 对真实雾训练数据的条件下，哪种结构选择的差异超过 seed 方差，以及这些差异在 indoor 场景是否保持。

**不能支持**：

- 任何「SOTA」或排行榜式结论。
- 「跨场景泛化」——除非补上 512 轨道或未发布数据。
- 「机制成立」——除非有单变量消融。
- 「盲测」——测试数据是公开的。

---

## 9. 需要你拍板的三件事

1. **有没有未公开的去雾数据？** 有 → 可以恢复成真正的 holdout，设计能干净很多；没有 → 接受「已知公开数据 + 受控提交」。
2. **参数上限 100k 还是 250k？** 100k 是你定的，我保留；评审建议 250k 作为校准候选，理由是 100k 可能把容量压到看不出结构差异。
3. **要不要排行榜？** 补不齐盲测与预算审计，就不该有排名。可以只发「配对差值 + 区间 + 消融」，不发名次。
