# 预注册：RDS 在 DL 任务上有没有增量（先冻结判据，暂不运行）

写于任何两臂运行之前。判定规则不改。

这份协议的用途只有一个：**在投入任何 RDS 功能开发之前，先验一个假设——完整契约在
DL 场景里到底有没有增量。**

如果没有，task-5 那套 rubric 判据就是给一个没人需要的系统加零件。

---

## 1. 待检验的假设

**H0（默认）**：RDS 的记录与判定层对 DL 研究没有增量，裸 agent 同样能做。
**H1（要验的）**：RDS 的「判据先冻结 + 失败留痕」能降低**口径修改次数**，且不显著
降低最终指标。

注意 H1 是合取式。只说「更少改口径」但指标掉了一大截，不算成立——那只是拿性能
换纪律，代价必须写进 README。

---

## 2. 任务

**OHaze 去雾，可学习参数 ≤ 50,000，前向次数不限，目标 test-A PSNR。**

选它的理由：真实任务、指标客观、数据已经在盘上、3 小时能跑完、没有合成世界。
细节见 `dehaze-benchmark-design-v2.md`。

数据：`train` 32 对（公开）、`dev` 8 对（公开）、`test-A` 5 对（RDS 侧持有，
只在终评算一次）。划分已落盘在 `ohaze-split.json`。

---

## 3. 两臂

| 臂 | 配置 |
|---|---|
| **裸臂** | 一个 coding agent，给同样的任务描述、同样的 train/dev、3h GPU。自由决定怎么做，自己记录。 |
| **RDS 臂** | 同一个 agent + RDS 的记录与判定层：跑前把判据（PSNR 口径、dev 选 checkpoint 规则、seed）冻结进 CAS，每次执行落回执，失败保留。 |

**硬要求**：RDS 臂必须真的调用模型。hard tier 上那 30 行 0 Codex token 的教训——
如果一个臂从头到尾没调模型，那它测的是确定性程序，不是「AI 帮我实现」。

同样的要求对裸臂成立：两臂的模型调用次数与 token 用量必须记录且可比。

---

## 4. 预注册的三个数

### 4.1 口径修改次数（主判据）

**定义**：在一次运行中，任何一次「看到 dev 结果之后，修改判据、指标定义、数据划分、
选模规则或 seed 清单」的行为，记 1 次。

- 裸臂：由事后审计对话记录统计（人工 + 逐条列出）。
- RDS 臂：判据存在 CAS 里带哈希，改一次就多一条事件，可自动计数。

**判据**：RDS 臂的次数 **< 裸臂**，且差异不能用「RDS 臂本来就没试那么多次」解释——
所以必须同时报「试跑次数」。

### 4.2 主指标差值 + 95% CI

**定义**：test-A 上两臂的 PSNR 配对差值，按图 bootstrap 算 95% 区间。

**判据**：
- 区间不含 0 且下界 > −0.5 dB → 「不显著降低」
- 区间下界 < −0.5 dB → 「拿性能换纪律」，代价要写进 README
- 区间跨越 0 且宽度 > 2 dB → **判 UNKNOWN**（见第 6 节：尺子可能不够）

### 4.3 无效 GPU 开销

**定义**：跑崩、超时、重复执行、因判据不清而返工的时间，占总 GPU 时的比例。

**判据**：RDS 臂不高于裸臂。如果更高，说明记账成本超过了它省下的返工。

---

## 5. 我已经测到的「尺子分辨率」（这是协议的地基）

在 dev 8 张上跑过 identity 与 DCP 两个基线，PSNR 口径与本协议一致：

| | 不加权均值 | 加权均值 |
|---|---|---|
| identity | 13.914 | 14.104 |
| DCP（暗通道，参数冻结） | 15.288 | 14.906 |
| 配对差 | **+1.374** | **+0.80** |

**配对差的 sd = 1.949，n = 8，t = 1.99，p ≈ 0.087 —— 不显著。**

两点后果，直接进协议：

1. **一个经典方法在 n=8 上都测不出显著差异。** 所以任何两臂差值只要小于 ~2 dB，
   在这套数据上就无法与噪声区分。
2. **必须用配对设计**，不能比两臂的平均 PSNR。配对差消掉图像间方差，这是唯一能
   提高分辨率的方式。

顺带证实了一件评审提过的事：dev 里 35 号只有 1.2MP，占总像素 1.2%，却贡献了
+5.80 dB 的离群值，把不加权均值从 0.80 抬到 1.37。**加权口径不是洁癖，是必需。**

## 6. 什么时候判 UNKNOWN 而不是「假设被推翻」

这一条比判据本身重要。三种情况必须落 UNKNOWN，不许写成阴性结论：

| 情况 | 记法 | 为什么 |
|---|---|---|
| 两臂差值区间宽度 > 2 dB | `UNKNOWN_INSUFFICIENT_POWER` | 尺子测不出，不是效应不存在 |
| 任一臂未在 3h 内产出可评模型 | `BLOCKED_BY_BUDGET` | 是预算问题，不是能力问题 |
| 两臂的模型调用量为 0 | `INVALID_ARM` | 测的是确定性程序 |

这是 RDS 自己的「三种终态」用在自己身上：`NO_SIGNAL` / `REFUTED` / `BLOCKED` 不能
塌缩成一个「失败」。

---

## 7. 不做什么

- 不做 EIG 选点。`rank_experiments` 保持现状，理由见 `dehaze-benchmark-design-v2.md`。
- 不改 Compass 的语法闭合问题（`compile_hypothesis` 那道 parse 门）。那是另一条线；
  本协议正是用来决定「要不要先动它」的。
- 不做排行榜。只有两臂，没有第三方队伍。
- 不追求 SOTA。主指标是差值，不是绝对分数。

---

## 8. 预算

- 每臂 3h GPU，单卡。两臂共 6h。
- 如果两臂都要真的调模型，token 预算也要对齐，记在同一个表里。
- 探测：先用 10 分钟跑通「数据加载 → 一个小模型 → dev 算 PSNR」这条链，占总预算
  ≤ 5%。探测失败则整份协议判 `BLOCKED_BY_BUDGET`。

---

## 9. 需要你确认的三件事

1. **两臂的 agent 是不是同一个模型**？如果是同一个，实验测的是「记录层」；如果不同，
   差异会混入模型能力。
2. **3h 是不是给两臂各自 3h**？我之前按各 3h 写的。如果你的资源只有一份 3h，那这份
   协议要改成「同一 3h 内交替」，结论强度会下降。
3. **test-A 现在就在盘上**（41–45 全分辨率 + 512 版）。RDS 臂会把它当 sealed，但裸臂
   如果拿到了同一台机器，也能读到。这一点无法技术性阻止，只能约定：**两臂运行在
   独立的目录里，test-A 只在评测脚本里出现**。接受这个限制吗？

---

## 10. 判定句

跑完之后，结论只能是下面三句之一：

- **H1 成立**：口径修改次数显著更少，且指标未显著降低。→ 投功能。
- **H1 不成立**：修改次数没有差异，或指标显著变差。→ 不投功能，把这个负结果写进
  README。
- **UNKNOWN**：尺子没分辨率（第 6 节）。→ 下一步是加数据或换指标，不是投功能。

**不许出现第四句。**
