# 冻结口径：iris 一组对照

写于任何模型准确率被计算之前。本文是这一次的全部口径。
跑分脚本先核对本文 SHA256，不一致就拒绝运行。

问题只有一个：在这一份冻结划分上，四个特征的逻辑回归，是否比只用花萼两列，在开发集上多对至少 2 个样本。

## 数据与划分

- `sklearn.datasets.load_iris`，150 行，4 列，3 类各 50。本机核对过的环境是 numpy 2.2.6、scikit-learn 1.9.1。
- 打乱：`numpy.random.Generator(numpy.random.PCG64(0)).permutation(150)`。
- 训练 105 行，开发 22 行，测试 23 行，按打乱后的顺序切。类别数是训练 37/33/35，开发 7/9/6，测试 6/8/9。
- 标准化只用训练集的均值和总体标准差（`ddof=0`）。标准差为 0 时用 1。开发集和测试集只用这组数，不参与计算。
- 两列模型和四列模型各自用自己用到的列计算标准化。

## 两个模型

- `sepal`：第 0、1 列，sepal length 与 sepal width。
- `all`：第 0 到 3 列。
- 两者都是 `LogisticRegression(C=1.0, solver="lbfgs", max_iter=500, tol=1e-4, random_state=0)`。不传 `multi_class`，因为 1.9 已没有这个参数。
- 不调学习率，不换 C，不换划分。多数类只作地板：训练集众数，平票取类别编号较小者。

## 判定

主比较只用开发集的判对个数。

- 相差 0 或 1 个样本：`INDISTINGUISHABLE`。
- `all` 至少多对 2 个：`ALL_FEATURES`。
- `sepal` 至少多对 2 个：`SEPAL`。
- 每个模型相对多数类也用同一条 2 个样本的线，只作附录，不改变主比较。

测试集在主比较写完之后只评一次。它不参与选择。若测试集的方向和开发集判定相反，结论仍以开发集为准，并写明不一致。

只有这一份划分、这一个 C。没有第二份协议，所以不写「四特征跨协议更优」。没有调用语言模型，所以不写「更省 token」。`model_identity` 固定为 `none`。
