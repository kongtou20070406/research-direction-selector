## 两句总纲

**学习有两段时间尺度，标准训练只优化第一段。** 拟合快，压缩慢，泛化在第二段结束时才到。所以「预算内没提升」不等于「方向死了」。

**症状不指向药方。** 「val 差 → 过拟合 → 加正则」是一条反射，不是推理；过拟合在现代过参数化模型里排第五位，而且就算真是它，也可能只是双下降的中间态。

## 症状 → 诊断链

### S1. 验证指标变差 / 泛化差

按先验顺序查，**前三个比「过拟合」常见得多**：

| 顺位 | 可能原因 | 怎么验 | ID |
|---|---|---|---|
| 1 | split 有问题（预处理/来源/时间窗不一致） | 看 step 0 的曲线；val 从一开始就差 → 基本是它 | D2a |
| 2 | 泛化相变还没到（晚发阶段） | 加 20-30% 预算跑一臂，看是否二次下降 | A1-A4, D3b |
| 3 | 路由/优化病理（前馈坍塌、LR 站错侧、warmup 被拿掉） | train 还在降但结构不对 → 不是容量问题 | C4, B2, B4 |
| 4 | 度量噪声（val 太小、类别不均） | 3 seeds，算区间 | D2d, D3 |
| 5 | **真的过拟合** | 四条子句全过才成立 | D1, D2e |

**第一个动作永远是加预算跑一臂，不是加正则。** 理由：它最便宜（同一份代码），而且能区分「中途」和「终点」。正则、早停、缩模型都会把你移动插值阈值的位置，可能从谷底挪到峰顶。

### S2. 训练 loss 不降 / 学不动

- 优化问题，不是数据问题：查 LR 是否在 descent 错误一侧（B2）、warmup 是否是大 batch 的稳定装置（B4）
- 深度非单调：加层可能更差，除非有残差稳定（A1）
- 前馈信号坍塌：参数量相当的网也可能因为路由不同而表现不同（C4）

### S3. 指标突然跳变（像「涌现」）

**先假设是度量制造的，不是模型突然会了。** 换成连续指标（token 级准确率）重画，峭壁通常会消失（E1）。只有换连续指标后仍陡，才是相变（A1）。

### S4. 复现不出来 / seed 方差大

单次运行是轶事，不是观察（D3 最后一行的判据）。三个来源：seed（3 个起）、**数据顺序**（改变表示几何，D1）、非确定性 kernel。记录顺序和数据顺序，否则两次运行不是一个模型。

### S5. 扩规模反而变差

- LR 不能跨 double descent 迁移：在小模型上调好的 LR 搬到大模型会站错位置（B2）
- 插值阈值移动：你从峰右边走到了峰上（D3b）
- muP 不是主杠杆，weight decay 可能更关键（B1）

**动作：重调 LR，并在新规模上画完整曲线，不要拿旧 LR 直接比。**

### S6. 换模型 / 更新后变差

先分离两类原因：**对齐让模型行为变了**（alignment tax，F3），还是**逻辑被改坏了**。当前 RDS 记录 token 但不记模型身份，这个区分事后做不了。

### S7. 想得越久越差

test-time scaling 是非单调的，加思考预算可能降低准确率（G2）。动作：给停止规则，别只加预算。

### S8. 加数据 / 加过滤没用

- 过滤是**关于下游任务的假设**，不是中性预处理（D2）
- 「需要更多数据」要先算重复 epoch 的反事实：多 epoch 有自己的 scaling 定律（D4）
- 数据受限是另一个区域，不是小一号的区域（E3）

### S9. 推理链看起来对，答案错

CoT 可以是**表演性的**：trace 不忠实反映产生答案的计算（G1）。**trace 不是 receipt**——这跟 RDS 自己「状态字段不是真相」是同一条规则。

### S10. loss 很低但实际不好 / 换分布就崩

perplexity 有几何盲点：低 loss 可能掩盖 OOD（E2）。动作：补位置度量，别用 perplexity 当覆盖度闸门。

## 任务形态 → 先验偏移

同一个症状，不同形态默认原因不同。

| 形态 | 真过拟合先验 | 先查 | 先修 |
|---|---|---|---|
| 单 epoch，数据 ≫ 参数 | **低** | split 卫生 | 修 split |
| 单 epoch，参数 ≫ 数据 | **低-中** | 是否 benign overfitting（拟合噪声后重新泛化） | 加长训练；别早停 |
| 小语料多 epoch | **高** | epoch 数与曲线拐点 | 这时才正则 |
| 微调预训练模型 | **高** | 记实例还是学任务（SFT 记忆） | 先整理数据，再 weight decay |
| toy 小数据（grokking 区） | **低但误导** | weight decay 是否在 Goldilocks 带 | 调 weight decay，不是"加正则"这一类 |
| 任何单 seed | **未知** | 先跑 2-3 seed | seed 方差 |

## 动作 → 代价

| 动作 | 代价 / 副作用 |
|---|---|
| 早停 | 停在第一峰顶。**最贵的错误反射**：把慢成功转成干净失败 |
| 加 weight decay | 移动插值阈值，不保证更好；太小太大都不 grok |
| 加 dropout | 单 epoch LM 预训练里不帮忙，可能有害（I1） |
| 缩模型 | 双下降下是非单调干预，可能从谷底挪到峰 |
| 加数据 | 相对安全，但费预算，且要同一「继续走」的对照臂才能确认 |
| 加自动化实验 | 若判据只看「预算内是否提升」，会把 S1 的中途全判成失败（D6） |

## 十个要打断的反射

| 反射 | 该查什么 |
|---|---|
| val 差 → 加正则 | S1：五个原因，过拟合最少见 |
| 没提升 → 想法失败 | A1-A4：晚发阶段；D6：三种终态 |
| 更深更大更好 | A1、C4：深度非单调、路由 |
| 指标跳了 → 能力涌现 | E1：度量可能制造跳变 |
| probe/SAE 说学了特征 X | C2：探针不是干预 |
| 推理链显示步骤 → 它在推理 | G1：trace 可以是表演 |
| 数据不够 → 加数据 | D4：先算重复 epoch 反事实 |
| 我们做了质量过滤 | D2：过滤是关于任务的假设 |
| test-time scaling 有帮助 | G2：非单调 |
| 模型更新后变差 → 逻辑坏了 | F3：先分离对齐变化 |

## 对 RDS 的三条直接约束

1. **三种终态，不是两种**：`NO_SIGNAL_WITHIN_BUDGET` / `REFUTED_WITH_EVIDENCE` / `BLOCKED_BY_CONDITION`。把第一个塌缩成「失败」就是系统级的反射（D6）。
2. **记录诊断，不只记录结果**：哪个原因被排除、怎么排除的。否则后来的人分不清反驳和预算短。
3. **别给「有没有加正则」打分**：那会训练出这条反射本身。给诊断质量打分——它命名了原因吗，什么能证伪它。
