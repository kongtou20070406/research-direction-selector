# PySR–RDS 接入红队审查

范围：依据接入方案第 7 节“公式能重放到什么范围”和 `docs/agent-rds-tools.md` 的工具语义，列出接入后最容易把搜索产物误当科学证据的失效模式。以下复现实验是构造示例，不代表已经运行或观察到结果。PySR 搜索、RDS 方言重放、账本回执和独立最终评价是不同环节，任何一环的通过都不能替代其余环节。

## 1. 噪声过拟合：搜索把随机误差刻进公式

**触发条件**：样本少、测量噪声大，却允许较多算子、常数和复杂度；反复查看验证结果后改搜索空间、种子或容差。候选数越多，偶然低训练 loss 越容易出现。PySR 的训练 loss 与 RDS 逐点容差回放口径不同；在含噪数据上，精确逐点相容本身也可能是错误目标。

**最小复现实验**（无需安装 PySR 也可构造输入；若已在隔离环境安装，命令仅作运行示意）：

```bash
python - <<'PY'
import numpy as np
rng = np.random.default_rng(7)
x = np.linspace(-1, 1, 12)
y = 1 + 2*x + rng.normal(0, 0.25, len(x))
# 将 (x, y) 写为开发集；再独立生成 x_test 与带同分布噪声的 y_test。
# 对照低复杂度线性模型与允许高阶幂/三角/指数项的 PySR 搜索。
PY
python run_pysr.py --data noisy.csv --maxsize 30 --niterations 1000
```

重复多个预先指定 seed，比较训练误差、未参与选模的测试误差和公式结构稳定性；测试集只在候选冻结后开启。

**检测方法**：预注册简单基线、噪声模型、评价指标和复杂度惩罚；多 seed 报告前沿、测试残差与候选结构稳定性。若训练误差下降而独立误差恶化，或公式结构随 seed 大幅变化，视为搜索不稳。训练集 `replay=CONSISTENT` 只能说明这批输入行未反驳公式，不能消除选择偏差。

**接入层闸门**：冻结开发集身份、搜索配置、种子集合和候选选择规则并绑定产物；将 PySR 原始 loss、复杂度及测试指标分开存储，禁止用测试集反复选模；使用预先声明的噪声/统计判据，不得看结果后放宽 tolerance。最终状态只能由原始测量回执经 frozen verifier 重放得到。

## 2. 常数外推：局部拟合把饱和关系误认成增长律

**触发条件**：观测输入范围窄、没有高端或边界测量；两条公式在已测范围近似重合，但在未测域增长阶、渐近值或符号不同。浮点常数被精确写入候选 AST，也不代表常数已被识别或适用域已确认。

**最小复现实验**：在 `x=0..2` 生成 `y=x/(1+x)`，拟合时只提供这一区间；并列比较饱和候选 `a*x/(b+x)` 与幂律候选 `d*x**p`。冻结候选后，在从未用于搜索的 `x=10, 100` 评价，报告预测分歧和误差。可用现有入口检查已提供观测行：

```bash
python -B scripts/rds_cli.py --root <project> compass tool replay --request replay.json
python -B scripts/rds_cli.py --root <project> compass tool rank --request rank.json
```

`replay.json` 的 rows 只放已绑定的开发测量；`rank.json` 可将高端可行点作为候选点进行分歧排序。未实际测量的点只能用于规划，不得冒充验证结果。

**检测方法**：画出已测范围和外推区间，比较候选在边界、极限及量纲约束上的行为；保留能在未测可行点区分 rival 的实验。记录预测区间/不确定性；单一拟合常数不得隐去其对数据范围和模型形式的依赖。

**接入层闸门**：候选必须携带显式适用域、单位、常数来源和定义域条件；在域外标记未检验，不将 `CONSISTENT` 扩展解释为域外支持。实验排序的 EIG 是给定 rivals 下的 advisory，不是购买指令；实际确认须经允许的执行路径、原始回执和独立评价。

## 3. 方言不兼容：转换静默改变公式语义

**触发条件**：PySR 公式含自定义 Julia 算子、未支持函数、模板语义、任意幂或特殊定义域；转换器为“尽量成功”而丢弃项、近似指数、改常数或重排变量。RDS 当前公式 AST 有 64 节点上限；直接幂仅接受常数有理指数，分母及绝对值均不超过 8。`exp/log/sin/cos/pi` 有受限重放语义，跨容差边界可为 `UNDECIDED`。

**最小复现实验**：准备三条候选：`x**1.3`、`sqrt(x)`、`custom_op(x)`。对正数域测试 `x**1.3` 的等价写法 `exp(1.3*log(x))`，并加入 `x=0`、负数点检查定义域差异；让转换器输出 AST 或明确拒绝原因。要求原式、转换式在边界和随机点上作差异对照，禁止把 `1.3` 四舍五入成可表示分数后继续。

```bash
python convert_pysr.py --expr 'x**1.3' --domain 'x>0' --strict
python -B scripts/rds_cli.py --root <project> compass tool replay --request converted-replay.json
```

**检测方法**：对 AST 做往返打印与语义差分；核对变量顺序、单位、定义域、奇点、分支及数值误差。检查每个表达式是否在节点和数值精度边界内。未支持表达式必须在报告中计数，不能静默过滤后宣称覆盖完整。

**接入层闸门**：转换采用严格白名单；任一算子、指数或定义域语义无法精确保留时返回 `UNSUPPORTED`/`UNKNOWN` 并保留原始表达式，不执行候选任意代码验真。禁止自动近似或静默重写；等价改写需声明域并独立验证。区分 RDS 的 AST 限制与 PySR complexity，记录真实 verifier/backend，不把 `CERTIFICATE_CHECKED` 写成 Lean 内核证明。

## 4. Holdout 泄漏：留出标签在流程中被污染

**触发条件**：holdout 点曾参与 PySR 拟合、特征/算子选择、seed 筛选、候选排序或人工调参；看过结果后将其称为最终测试；把旧测量回执晚导入当作候选提交后的新预测。单传 measurement IDs 不能证明数据未曝光。`compass tool holdout` 有账本前提，但不自动证明点从未用于拟合、保密或后提交。

**最小复现实验**：先将 `x=0..9` 及 `x=5` 的测量写入 CSV，使用全表拟合/选模，再把 `x=5` 的 ID 传给 holdout；预期独立性检查必须拒绝或返回未知，即使回放一致。另做正确对照：候选冻结并留存时间戳/产物摘要后，才在原项目执行 `x=5` 测量并结算 receipt。可按工具草案尝试：

```bash
python -B scripts/rds_cli.py --root <project> compass tool holdout --request holdout.json
```

若当前 CLI 没有该独立入口或项目不满足 Compass 账本前提，应由既有独立评价路线处理，不能退化成普通 `replay`。

**检测方法**：核查数据血缘、测量时间与候选冻结时间、访问/选择日志和账本依赖；确认 holdout 从搜索及候选选择输入中排除。检查 receipt 绑定原始输出 bytes；缺失、篡改、过期或身份不明一律未知。holdout 被用于修订后，该轮数据转为开发证据，下一次确认须用新的未暴露数据。

**接入层闸门**：独立性由现有 ProjectStore/CAS/TMS 中可审计的来源与时序证据判定，不接受调用者自报“未见”。receipt 无效、holdout 已参与任何决策或来源不明时 fail closed 为 `UNKNOWN`/拒绝；不得改用 agent 提交的 rows。候选冻结后产生并结算的测量才可能成为新预测证据，结论仍交 frozen independent verifier。

## 5. 搜索成本失控：预算只记了拟合时间的一部分

**触发条件**：首次安装 Julia/依赖及编译耗时被漏记；PySR 多 seed、重试、checkpoint 恢复、候选转换和独立评价不计成本；仅给内部搜索设超时，外层进程或一次 agent 调用仍可超支。失败或超时后自动重跑，造成重复付费或重复实验。

**最小复现实验**：设置极小总预算与短外层超时，冷启动运行一次，再用多个 seed 搜索；记录环境准备、编译、每次搜索、候选转换、评价和 Agent token 的墙钟/CPU/费用。故意令第二次搜索超时，确认系统记录部分 stdout/stderr、阶段/attempt、已消耗成本和失败回执，且不会自动重买。

```bash
python run_pysr.py --data tiny.csv --niterations 100000 --timeout 2
```

命令仅用于隔离的微型数据和已声明预算，不要为触发超时扩大 RDS pilot/campaign 上限。

**检测方法**：将总成本账与执行 receipt、stdout/stderr 摘要、阶段和 attempt 逐项对账；包含安装、编译、失败、恢复、候选独立评价、测量、Agent token 与墙钟。核对每次调用前预算预留及调用后结算；未知成本不能按零处理。

**接入层闸门**：PySR 作为原项目已声明执行的一部分，绑定命令、环境/依赖版本、输入身份、种子、产物与成本到现有账本；不建旁路账本或未记账子进程。外层强制超时和预算上限，不因内部超时扩大既有 pilot/campaign cap。超时/回执缺失时记录部分输出和已收费成本并 fail closed；不得静默重跑或把资源失败当科学反例。

## 不能宣称什么

- 不能因 PySR 找到一个低 loss、短公式或 Pareto 前沿候选，就宣称发现定律、机制或真实因果关系。
- 不能因 RDS `replay` 返回 `CONSISTENT`，就宣称 `SUPPORT`；它只说明提供的行与候选在给定容差下相容。纯计算入口接收的 rows 不证明其来自 receipt。
- 不能把有限公式重放、证书检查或 holdout 相容写成全域证明、语义正确性证明或自动保证的独立确认。
- 不能把不支持的 PySR 算子静默删除/近似后仍称候选等价，也不能把 AST 的有限覆盖说成搜索完整。
- 不能把候选排序的 EIG、预测分歧、低训练误差或留出点上的单次命中说成实验收益或科学确认。
- 不能把已看过、已参与拟合/选模的点称为独立 holdout；不能把旧回执的晚导入说成冻结候选后的新预测。
- 不能只报成功候选或搜索时间而隐藏失败、未知、不可转换候选、超支与资源成本；也不能据此宣称 PySR+RDS 已带来科研收益。收益主张需按预注册、同模型同预算、未见且不可穷举任务域比较独立复核正确率，假认证率不得上升，并报告每正确解 token 成本。
