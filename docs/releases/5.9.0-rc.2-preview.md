# RDS 5.9.0-rc.2 preview

This preview addresses overly coarse next-step advice: a sourced unmet goal
predicate calls for diagnosing that scoped gap, and an A-to-B-to-A choice history
calls for reviewing those decisions. Neither alone requires changing the original
problem. Recorded rejected routes and families retain their scoped reformulation
review. The original goal, acceptance predicates, budget, evidence and execution
authority remain in force.

The decision-semantics and reference-ledger compatibility corrections are tracked
in [Issue #254](https://github.com/kongtou20070406/research-direction-selector/issues/254)
and [Issue #255](https://github.com/kongtou20070406/research-direction-selector/issues/255).
The [v5.9.0-rc.2 release page](https://github.com/kongtou20070406/research-direction-selector/releases/tag/v5.9.0-rc.2)
identifies the exact published commit, validation results and downloadable source
and host packages. The latest stable release remains 5.8.0.

## Decision and continuation fixes

- Use the additive `DIAGNOSE_GOAL_GAP` next-step label for sourced unmet goal or
  affirmative predicates, preserving missing or conflicting evidence as
  `UNKNOWN`. A local failure does not establish a capacity bound or identify a
  causal mechanism.
- Use `REVIEW_DECISION_HISTORY` for choice-order warnings. Preserve the warning
  as history evidence without forcing structural reconstruction of a currently
  satisfied goal.
- Keep the existing `next_move` string in brief JSON and add a bounded reason,
  so callers can distinguish the affected evidence and scope without losing the
  full report's original CAS locator.
- Keep pending and unresolved confirmation results `UNKNOWN`; a completed
  negative confirmation still refutes its declared acceptance predicate.
- Recover failed or interrupted attempts only when their receipt is missing.
  Review an already recorded execution failure using its original evidence,
  without repeatedly collecting the same completed attempt.
- Report `RESOURCE_BLOCKED` with the particular resource shortfalls when no
  otherwise-ready route fits the remaining budget. An inability to dispatch is
  separate from a refuted research goal. Completed attempts, spent budget and
  reservations remain recorded.
- Read explicitly supported reference-state versions, including stable 5.8.0
  and the previous 5.9.0-rc.1 preview, without rewriting their stored version or
  SQLite state. The contract digest remains checked. Unlisted versions are
  rejected, and a changed engine binding still blocks new execution until the
  existing new-contract or versioned-review requirement is satisfied.

These are scoped engineering corrections. A next-step label is advice, not
scientific acceptance or permission to spend resources.

## Validation and limits

The release requires regression checks of the changed Advisor and continuation
paths, public status/read compatibility, unsupported versions, contract integrity
and changed-engine admission. Preserve original baseline failures and compare
them with the candidate on the same declared cases. The release page must bind
the tag, source and host packages to one exact commit and identify the checks
that actually ran, including skips and unavailable coverage.

Synthetic regressions and CI assess the supported software behavior within their
declared scope. They do not demonstrate scientific gain, independent research
autonomy, learned ranking quality or improved research policy. Those claims
remain unmeasured or unproven; the matched-model evaluation remains in
[Issue #166](https://github.com/kongtou20070406/research-direction-selector/issues/166).
