# RDS 6.0.0-rc.1 preview

The 6.0 generation continues the pipeline refactor: separate shared identity
helpers from the CLI, move presentation resources out of Python, and bind a
known research workspace to its original project ledger. These changes make
module ownership and continuation constraints explicit. The refactor is
incremental; this preview does not claim that every pipeline stage has been
extracted or independently accepted.

## Pipeline and module boundaries

The mainline #312 increment adds `scripts/rds_core.py`, a stdlib-only module
with `canonical(value)`, `object_digest(value)` and `bytes_digest(raw)`.
Canonical JSON remains compact, sorted, UTF-8 compatible and rejects non-finite
numbers. Object identity hashes canonical JSON; byte identity hashes the raw
buffer unchanged. In `rds_cli.py`, the existing `canonical()` and `digest()`
entry points delegate to the new module while preserving their earlier
serialization and digest behavior, including the CLI digest's bytes case.

This extraction covers the CLI helpers only. Other stores have their own
identity contracts; for example, `rds_project.digest()` hashes canonical JSON.
Callers must not replace every digest with raw-byte hashing or assume all
modules have moved to `rds_core`. #312 introduces no workspace-binding code,
run/budget change or additional writer path. Its `engine_id()` now also binds
the bytes of `rds_core.py`: changing that module changes the reference engine
identity and remains subject to the existing execution and receipt-review
guards.

The campaign changes use `rds_campaign.py` for workspace identity and
`rds_mutation.py` for short cross-process mutation scopes. CLI, store and
worker callers share those guards. This is an ownership boundary around
admission and publication, not a new scientific decision rule. External work
runs outside the short publication lock; its original accounting and recovery
obligations remain in force.

## Presentation resources and packaging

#310 moves embedded dashboard and hypergraph HTML, CSS, JavaScript, license
text and ordered Replica patches into eleven runtime files under
`scripts/assets/`. Loaders resolve these resources relative to `__file__` and
decode raw UTF-8 bytes. The public presentation constants and rendering
interfaces, script-data escaping and offline single-file exports are retained.
This reduces the size of the Python presentation modules; it does not
establish a reduction in total application code or a new visualization capability.

Distributors must ship the assets with the Python modules. `build_plugins.py`
and copied self-development snapshots include indexed resources recursively;
new resources must be staged before building. A source assembled after #312
also needs `rds_core.py`, which plugin packaging selects as a tracked script.
Copying only the old Python entry file is no longer a complete distribution.

QUICK's static Python input discovery does not infer runtime asset reads.
Callers executing a renderer through QUICK must explicitly bind each required
resource with `--bind data=<path>`. Changed bound assets refuse reuse of an
existing job instead of silently rerendering it. The 128-file and 64-MiB input
bounds are unchanged. See [presentation assets](../presentation-assets.md) for
resource layout and optional pinned Replica dependencies.

## Workspace ownership and prevention of resets

Campaign binding is opt-in; existing workflows remain `UNBOUND` by default.
`project bind-workspace --workspace-root <existing-workspace>` binds an
identified workspace to an **existing** canonical project. The
`.rds-campaign.json` marker contains identity pointers: canonical workspace and
project roots, the genesis contract digest, a binding nonce and its native
ledger event identity. It does not copy research state or reset budget.

Discovery within the bound workspace prioritizes that canonical project,
including from sibling directories. The returned absolute binding path must
be retained as `RDS_CAMPAIGN_BINDING` in subsequent commands and subprocesses.
Applicable ancestor markers and the required environment pointer are verified
against the original ledger; missing, damaged, replaced or conflicting
identities fail closed rather than falling back to an unbound workspace.

Within that inherited campaign context, a new root, `--separate-project`,
`--supersedes`, a copy of the contract, the legacy reference runner or public
QUICK `exec` cannot replace the original ledger or open another experiment.
Continue through canonical `project create`, `project execute` or owned
`project advance`. Original failed attempts, receipts, checkpoints, exposure,
spent budget and reservations remain history; binding creates no execution
allowance.

Publication requires settlement of all native workspace ledgers and recursively
retained jobs. A terminal receipt alone may be insufficient: owned Advisor
collection, model-result processing and prospective QUICK completion
checkpoints must also be recorded by their original producer. Incomplete or
over-limit inventory refuses binding. Publication and cooperating native
writers share the mutation lock, including before a marker exists. Interrupted
publication can restore the original marker from its unique verified native
event; it cannot substitute another ledger or a fresh nonce. See
[campaign binding and recovery](../project-lifecycle.md#bind-a-known-campaign-workspace).

These protections cover cooperating RDS entry points with inherited campaign
context. They are not an OS sandbox or protection against direct SQL, backup
rollback, arbitrary host code, or deliberate removal/bypass of that context.
Further #311 repairs remain under review; wider closure is **UNKNOWN** here.

## Public interfaces and affected callers

| Caller | Required adjustment or retained contract |
| --- | --- |
| CLI/JSON consumers | Keep documented command and schema handling. The core extraction preserves CLI helper bytes; do not infer a wholesale schema migration from the major label. |
| Python reference-ledger writers | Raw writable `RDSState.connect()` is refused. Use `with state.transaction(create=...) as (db, snapshot):` for writes; the guard remains held through commit and close. `connect(readonly=True)` remains a reader. |
| Host integrations and subprocess launchers | Propagate the returned absolute `RDS_CAMPAIGN_BINDING` path and use discovery's canonical `project_root`; a missing binding is an error to repair. |
| Detached QUICK, reference-runner and tool-validation callers | In a bound campaign, do not use detached jobs or public qualification preparation to obtain another allowance. Already registered tools retain their read-only qualification/receipt checks. |
| Renderer and package builders | Include `scripts/assets/`; bind runtime resources explicitly in QUICK. Include `rds_core.py` when building from a tree containing #312. |
| Stored reference-state readers/executors | Supported old state remains readable without rewriting its stored version. Read compatibility does not authorize execution with a changed engine identity. |

## Session observation and conversation behavior

The #315 increment adds `rds_session.py observe` and `list`, which inspect the
available session state without creating directories, databases or usage rows.
Trusted session activation remains unavailable: `enable` returns `PENDING`
without granting new admission. Skill loading is `UNKNOWN`, and automatic
application remains `UNKNOWN_NOT_PREVENTED`.

CLI `--version`, top-level `--help`, and the supported `status` read flags bypass
usage logging, including accepted unique option prefixes. `project discover`
keeps its ordinary logged path: SQLite WAL readers can create auxiliary files,
and an unavailable default usage location can cause a project-local fallback.
See [CLI usage](../cli-usage.md) and the [onboarding guide](../onboarding.md).

The conversation hook's startup message describes its own context injection
only. It cannot attest that the host did not load a Skill or that an agent used
RDS for every action. Invocation messages describe the observed call and its
phase; a returned call is not scientific acceptance. Full external-action
reconciliation and protection against deliberate host-level bypass remain
unverified.

#314 moves longer procedures into packaged `references/skill-routes/` documents
while retaining the inline authorization, budget, evidence and recovery rules.
Advisor activation applies to an existing QUICK project; a newly created FULL
project does not need an additional activation attempt.

The current host-validation target is **Codex and OMP**. Claude Code package
files are retained, but this preview does not establish live Claude Code
validation. Package smoke checks also do not establish a verified human-visible
status surface or a trusted activation channel on either target host. Help test
these boundaries and report the host version, exact RDS revision, observed
behavior and sanitized reproduction in an
[issue](https://github.com/kongtou20070406/research-direction-selector/issues).

## Migration and continuation

1. Pin the exact old and proposed source/package revisions. Preserve a
   restorable copy of the original ledger, CAS, contract/input bindings,
   receipts, checkpoints and any campaign marker before switching installations.
   Retain failed outcomes, charged cost and pending reservations; do not edit
   stored versions or hashes to make an upgrade appear accepted.
2. Inspect the existing project with the old trusted installation and settle
   pending original operations before binding. Resume their own bookkeeping
   rather than relaunching completed experiments. For an original QUICK job
   with a missing completion checkpoint, use its original root and
   `project recover --id <original-run>` as documented in the lifecycle guide.
3. Install a complete source/host package, including the extracted assets and,
   where present, `rds_core.py`. Adapt Python writers to the transaction API and
   renderer callers to explicit data bindings. Check relocated imports and
   actual exports rather than testing only from the source directory.
4. Check supported reference-state reads without mutation. The PR #313 reader
   supports the listed legacy versions through `5.8.0`, `5.9.0-rc.1`,
   `5.9.0-rc.2` and its current `6.0.0-rc.1` label; unlisted versions remain
   rejected and contract integrity remains mandatory. Consult the exact
   installation's readable-version list in the [versioning policy](../versioning.md).
   This reference-state check is not an automatic project-ledger converter.
5. If a reference engine binding differs, respect the new-contract requirement
   for new execution and versioned review requirement for old receipts. The
   version-label change alters the CLI source hash; #312 also adds the core
   source binding. Preserve the old ledger and original acceptance scope. Do
   not overwrite engine hashes, discard costs or initialize a replacement
   inside a bound campaign to bypass a refusal. An automatic in-place engine
   migration retaining old execution authority is not provided by this preview.
6. When the researcher has identified the existing canonical project and
   workspace, bind once, retain the returned environment pointer and rediscover
   the canonical root. If a binding or ledger is unavailable, repair its
   verified original identity. Continue only under the original command,
   resource, evidence and recovery gates; binding adds no authorization.

original evidence, not repeatedly collected. `RESOURCE_BLOCKED` distinguishes
budget shortfalls from refuted goals. These are scoped software behaviors,
not new scientific acceptance or resource authority.

## Validation and material limits

Focused checks are available as `python -B -m unittest <module>` with the
checkout's `tests` directory on `PYTHONPATH`:

- `test_rds_plugin_package`, `test_rds_presentation_assets`: relocated host
  packages, asset bytes, exports and changed-resource refusal.
- `test_rds_campaign_binding`, `test_rds_campaign_publication`,
  `test_rds_campaign_record_publication`: original identity, retained work,
  publication races and reset refusal.
- `test_rds_release_compatibility`, `test_rds_skill_routes`: supported
  reference-state reads, integrity, changed-engine refusal and documented CLI
  reachability.
- `test_rds_core`: helper identity and relocated imports, **only in a source
  tree containing #312**; unavailable on PR #313's original starting tree.

These are coverage pointers, not a statement that every check passed on one
release revision. Bind actual local results, skips, dependency limits and the
required Windows/Ubuntu, Python, native and Lean CI to the eventual exact
release commit. Earlier-revision passes do not supply missing release evidence.
Full pipeline acceptance, final package publication and real browser visual
acceptance are not established by this documentation update.

Scientific gain, independent research autonomy, learned ranking quality and
improved research policy remain **UNKNOWN / unmeasured**. Synthetic regressions,
serialization equivalence, receipt validity and green CI establish only their
declared software checks. Matched-model research evaluation remains separate
in [Issue #166](https://github.com/kongtou20070406/research-direction-selector/issues/166).
