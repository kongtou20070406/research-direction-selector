# RDS 6.0.0

6.0.0 adds **Compass**. Compass compiles one declaration into the existing
kernel contract and then runs the research loop unattended:
- the Advisor picks the highest-EIG experiment;
- when evidence stalls, Compass escapes the basin with a probe, an abductive jump or goal-bound RSI;
- results are verified exactly, with Lean or with a router-checked certificate;
- a report is recomputed from the original receipts.

Compass adds no second ledger, scheduler or database. Every Compass fact is a
hash-chained `COMPASS_*` event in the project ledger. Measurements remain
`INPUT_REPORTED`, and `scientific_support` is always `UNKNOWN`. See
[Compass](../compass.md) for the design.

## Compatibility

- **Ledger reading.** The reference-state reader adds `6.0.0-rc.1` to the readable list. Older listed versions keep their stored bytes on read-only status.
- **Existing commands.** Projects without a Compass plan see no new events. `project init` and `project drive` behave as before unless `--declaration` or `--compass` is given.
- **Interrupt receipts.** Kernel interrupt handling changed observably. An outer interrupt during `project execute` now produces `process_status: INTERRUPTED` instead of `FAILED`, and the exception propagates to the caller after the receipt is written.
- **Advance output.** A non-launching `project advance` result gains an additive `launch` field. Existing keys are unchanged, and `receipt` stays absent.
- **Repair.** `request_repair` now fails closed when bound code changed after preparation. The fix is to prepare again from the current binding.

- **Affected existing suites:** project, autonomy, workspace, campaign, quick, capability requirement, jump-kernel routes, import graph, entrypoint imports, offline contracts, guard values, skill routes, progressive routes and plugin package.
- **Full suite:** `python3.12 -B -m unittest discover -s tests`, with `python` on `PATH`, on the tree with the hard-tier follow-up and all seven review rounds: 3787 tests OK and 104 skipped, exit 0. Skips are environment-gated: Lean, Node, torch, and Linux-only, Windows-only or replica-root cases.

The SIGTERM test sent `os.kill` to its own process, which on Windows is `TerminateProcess` and ended the test runner. The tail-tamper test errored. - **End-to-end CLI checks:**

  - a popcount gap is closed by RSI and reused from the library (`ORIGIN_VERIFIED`);
  - a trap world retracts its tool and ends `SEARCH_EXHAUSTED`;
  - SIGTERM gives `INTERRUPTED` with rc 2, and a rerun resumes through `-a2` to `GOAL_IDENTIFIED`.

Baseline test repairs made while validating:

## Independent red-team pass

Before release, the Codex CLI (`gpt-6.1-sol`, reasoning `xhigh`, default service tier) ran once as an adversarial tester on a disposable copy of the candidate. Its brief was to break the Compass invariants and prove each finding with a failing test. It reported 9 findings, and all 9 tests failed on the candidate. Eight were real defects and are fixed; their reproductions are permanent regressions in `tests/test_rds_compass_adversarial.py`.

| Finding | Defect | Fix |
|---|---|---|
| Changed `stdout.bin` still allowed `GOAL_IDENTIFIED` | Verification re-hashed only the declared output | Every receipt-bound artifact is re-hashed (`ARTIFACT_HASH_MISMATCH`/`ARTIFACT_MISSING`) |
| Late ingestion turned old receipts into "novel" confirmations | Novelty used Compass ingestion order | Novel only if the run started after the rulebook's ledger row was written (by write time) and its receipt settled after that row (by ledger event order) |
| IMPROVE recommended an arm whose output no longer verified | Stale arms kept cached samples | `STALE_EVIDENCE` verdict; the drive ends `JUDGMENT_REQUIRED` |
| SIGTERM between RUNNING and child launch left a RUNNING run without a receipt | Gap before the kernel's settlement handler | The pre-launch window settles `INTERRUPTED` and re-raises |
| `compass report` copied the stored verification | Report trusted a stored status | Report re-checks receipt bindings at read time (`report_recheck`) |
| A jump response written while new evidence arrived was adopted | No freshness check after the agent call | `STALE_RESPONSE` if the Compass head or receipt set moved during the response; nothing is adopted |
| An agent rulebook reading a tool feature survived tool retraction as `REFUTED` | Premises came only from the agent | Premises are derived from the tool features any rulebook reads |
| A tampered tail row passed chain validation | No successor binds the tail | Per-row `row_sha256` and consecutive `seq` checks |

The ninth finding was not accepted as a defect. A FAILED purchase let an experiment with the same rival partition be bought next. A failed run yields no measurement, so that partition was never observed, and buying another input is legitimate. [Compass](../compass.md) now states this.

The Codex review of [#357](https://github.com/kongtou20070406/research-direction-selector/pull/357) found twenty more defects over seven review rounds. All twenty are fixed, with regressions in the adversarial and drive test files:

| Finding | Fix |
|---|---|
| An IMPROVE declaration without `min_gain` or `max_degradation` still ended `IMPROVEMENT_EVALUATED` | Unknown thresholds or an unmeasured baseline end the drive `JUDGMENT_REQUIRED` and name the unknown thresholds |
| `higher_is_better: "false"` was read as true | The declaration requires a JSON boolean |
| An IDENTIFY_LAW hypothesis could omit the goal observable and crash certificate verification | Declared, adapted and proposed hypotheses must predict `goal.observable` |
| An RSI tool-runner timeout aborted the drive with no ledger record | A timeout or failed runner is recorded as `TOOL_REJECTED` (`TOOL_RUNNER_TIMEOUT` or `TOOL_RUNNER_FAILED`), with phase, stream hashes and wall time. The same tools are not re-run at the same evidence count |
| A timed-out jump agent's partial output was discarded, and the stdout hash covered decoded text instead of the raw bytes | `DISPOSITION` binds the input, stdout and stderr by raw-byte SHA-256. A timeout is `AGENT_TIMEOUT` with partial-stream hashes |
| `budget.experiments: "4"` initialized, then crashed the drive | The value must be an integer from 0 to the number of attempt slots |
| `integer: "false"` was read as true | The value must be a JSON boolean |
| A receipt with only a side observable counted as a novel confirmation of the goal law | For IDENTIFY_LAW, only receipts that report the goal observable confirm |
| `timeout_seconds: true` initialized as a one-second timeout | Timeouts and wall budgets must be JSON numbers, not booleans |
| An IMPROVE arm measured on other samples than the baseline still ended `IMPROVEMENT_EVALUATED` | `UNMEASURED_OR_SAMPLE_MISMATCH` arms end the drive `JUDGMENT_REQUIRED` and are named |
| The stated rule accepted a mean gain of `min_gain`, but the code also required a positive gain, so `min_gain: 0` or below behaved differently from the rule | The rule reads "mean gain > 0 and >= `min_gain`", and a negative `min_gain` is rejected at `init` |
| An IMPROVE metric without `higher_is_better` was silently read as higher-is-better, so a loss metric would recommend the worse arm | The direction is listed as unknown; every arm is `JUDGMENT_REQUIRED` and the handoff names `higher_is_better` |
| Two live rulebooks that both predicted an observable with no tolerance crashed verification with `KeyError` | Equivalence compares only observables with a tolerance, as replay does. The claim leaves such an observable out of `predict` and names it under `unadjudicated` |
| A retained observation whose receipt row was missing crashed verification with `KeyError` | The observation is stale evidence (`RECEIPT_MISSING`); the drive ends `JUDGMENT_REQUIRED` |
| An IMPROVE metric without a tolerance was compared exactly and could be accepted | Every arm is `JUDGMENT_REQUIRED` and the handoff names `tolerance` |
| `compass report` flagged bindings that went stale after verification but kept the stored claim and recommended arm | The report's claim falls to `NOT_ESTABLISHED`, IMPROVE verdicts are recomputed and no arm is recommended; the stored conclusion is kept under `*_at_verification` |
| Equivalence skipped a point where one rulebook was `NOT_APPLICABLE` and the other `UNDEFINED`, so a separating candidate could be missed | Differing prediction statuses make two rulebooks non-equivalent |
| A resumed drive kept deciding and buying from ingested evidence whose receipt bytes had changed | Bindings are re-checked before every rival, ranking or purchase; a stale one ends the drive through `VERIFY` |
| An agent proposal could reuse a retained or same-response hypothesis id, overwriting a rulebook or aborting the drive | Such a rulebook is not admitted (`ID_TAKEN`) |
| Candidate ids differing only in case initialized, then collided on one output file on a case-insensitive filesystem | `init` rejects them on every platform |

A twelfth finding did not reproduce. It said that a predicted observable with no declared tolerance was replayed with a zero tolerance. Replay rows never carry such a cell, so the cell was already `UNKNOWN`. The zero-tolerance fallback is gone, and replay itself now counts an observable with no tolerance as `UNKNOWN`. A regression in `tests/test_rds_compass_drive.py` checks both paths.

## Benchmark

[`benchmark/compass`](../../benchmark/compass/README.md) compares its arms on four multi-trap worlds. All arms run through the same kernel receipts, and each result file carries its bundle SHA-256.

The deterministic arms are N=1:

| Arm | Verified discoveries | False certifications | Repeat-refutation waste | Experiments |
|---|---|---|---|---|
| Greedy ratchet | 0 / 4 | 3 | 0 | 12 |
| Bare agent (simulated policy) | 0 / 4 | 3 | 0 | 27 |
| Compass | 5 / 5 runs | 0 | 0 | 61 |

Compass's 61 experiments come from the current stopping rule, which spends the budget on refutation attempts before a claim. The earlier rule used 29 (see the hard-tier follow-up below).

Tool compounding on `capability-gap`:
- **Session 1:** tried 16 generated tools before `divisors` qualified.
- **Session 2:** tried 1, the library offer, re-qualified against its own receipts.

The real-model arms (opt-in, Codex CLI `gpt-6.1-sol`, `xhigh`, default tier) are N=3:

| Arm | Verified discoveries | False certifications | Contaminated | Experiments |
|---|---|---|---|---|
| Real bare agent (`codex_agent`) | 12 / 12 runs | 0 | 0 | 112 |
| Compass with Codex jumps (`compass_codex`) | 15 / 15 runs | 0 | 0 | 87 |

The real agent avoided every trap, mostly by measuring the whole declared domain. It did so in 11 of 12 runs. This run was recorded at `5baa04a`, under the earlier stopping rule. There, the arms separated only on cost: Compass's first sessions used 23 experiments per trial, against 37.3 on average for the real agent. That margin came from the stopping rule the hard tier showed to be unsafe, so it is not claimed. Read the simulated bare-agent row as a policy result, not a frontier-model result.

The transcripts and a hash manifest are in `benchmark/compass/results/codex-transcripts/`. Twelve agent streams had the host temp path and account name redacted.

## Hard tier and follow-up fixes

A hard tier was pre-registered on branch `bench/compass-hard-tier` (`HARD-PROTOCOL.md`, `hard-protocol.json`) before any arm ran. It has four tasks whose discriminating checks cost real budget, in priced units, on domains of up to 1200 inputs. The real-model arms ran N=3 with the same Codex model and caps. Its outcomes, unpatched:

| Task | `codex_agent` | `compass_codex` | Compass mechanism | Comparison |
|---|---|---|---|---|
| `hard-sparse-budget` | 3 verified, mean 7 units | 3 verified, mean 7 units | held | tie |
| `hard-posthoc-picking` | 3 verified, mean 9.3 units | 3 false certifications | failed | `codex_agent` |
| `hard-belief-drift` (2 sessions) | 6 verified, mean 7 units | 3 no claim, 3 false certifications | failed | `codex_agent` |
| `hard-near-rival` | 2 verified, 1 no claim | 3 verified, mean 11 units | held | `compass_codex` |

The pre-registered gate did not pass on any task: the real bare agent made no false certification, so these traps did not bite the frontier model. `compass_codex` used 0 Codex tokens in all 30 rows. That arm never called the model, so it measured deterministic Compass.

The causes, each fixed with a regression in `tests/test_rds_compass_hard_followup.py` (9 of its 11 tests fail on `26004a1`; the other two are guards):
- **Id tie-break.** Equal-EIG candidates were ordered by id. In `hard-belief-drift` session 2 Compass bought `x1` and then `x10`, where `x + 5·nonzero10(x)` agrees with `x+5`, and two novel predictions certified `x+5`. Reproduced on a 64-input surrogate, the decision record shows `x10` bought by EIG among equal-gain candidates (`x10` sorts before `x2`). Ties now go to the candidate farthest from the evidence.
- **Stopping rule.** Two novel predictions cannot rule out a sparse exception. With the coverage tie-break, the drive test world with exceptions at 11 and 13 was certified on 6 of 17 inputs. It had passed before only because id order bought those inputs. By default Compass now spends the remaining budget on refutation attempts before it claims, and every claim reports its coverage.
- **Agent never asked.** The jump agent was called only to dispose of machine fits. When synthesis found nothing, which is exactly when a model could help, the drive ended without asking. The packet now requests `PROPOSALS` in that case.
- **No replication.** IMPROVE judged each `_r2` run as an unrelated arm and recommended a variant whose replication it never bought. A candidate may now declare `replicates: <arm>`, and an arm is accepted only if every declared run passes the rule.
- **Rulebook size.** Found while fixing the above: synthesis could compose a regime split or residual correction of up to 33 nodes, but rulebooks compiled only up to 15, so a longer campaign could crash in `escape`. Rulebooks now compile up to 64 nodes; each synthesized part stays within 15.

A post-hoc check of deterministic Compass on the same worlds, run after their outcomes were known, is **not** evidence of generalization:
- `hard-sparse-budget` and `hard-near-rival` verify, now spending the full 15 and 12 units.
- `hard-belief-drift` makes no claim in either session, instead of a false certification. The deterministic grammar cannot express the law.
- `hard-posthoc-picking` still fails as registered, because its declaration has no structured `replicates`. With `replicates` declared, it accepts `variant_1` after replicating `variant_6` (which fails) and `variant_1`, at 12 units.

What is still missing before a claim that Compass improves a frontier model:
- fresh, pre-registered worlds run under the fixed policy, with `compass_codex` actually calling the model;
- an external benchmark.

## Prior art consulted

These three repositories were reviewed from their source and documentation; none of their code was run or copied:
- [morluto/jacobian](https://github.com/morluto/jacobian)
- [morluto/leantoken](https://github.com/morluto/leantoken)
- [morluto/gitcontribute](https://github.com/morluto/gitcontribute)

6.0.0 already follows several of the same rules:
- a timeout or interrupt is never a negative conclusion (`INTERRUPTED` is not a measurement);
- Advisor decisions are bound to the state head they were computed from;
- repair inputs are hash-checked and fail closed;
- oracle expected values come from replayed receipts, never from stored fixtures;
- equivalent experiments are excluded.

Not adopted in 6.0.0, and candidates for later work:
- a sealed holdout that is consumed on viewing, for the benchmark;
- base vs candidate replay comparison with repeat-stability (`Flaky`) classes;
- TMS revalidation outcomes (`Carried`/`Changed`/`Missing`/`Unmapped`) when CAS content moves;
- BM25 tool discovery and near-duplicate rejection for RSI offers;
- coverage-first experiment batches;
- reporting generation recall separately from selection recall.

## Limits

- **No Lean toolchain.** Lean 4 is not installed here. `lean_vector_obligation` fell back to `rds_python_closed_rational` (`CERTIFICATE_CHECKED`), and the result says so.
- **Router search unused.** Compass builds its polynomial certificate with exact `Fraction` elimination, and only the router's independent checker replays it. The router's SymPy search path is not exercised by Compass.
- **Windows simulated.** Windows path aliasing was tested by simulation on macOS, not on a Windows host.
- **Toy benchmark.**
  - The benchmark uses synthetic toy worlds with small declared domains.
  - The simulated bare-agent arm is a stated policy, not a model.
  - The real-model arms are N=3 on one model and provider.
  - A real frontier agent matched Compass on correctness by measuring exhaustively. No task yet makes exhaustive measurement impossible.
  - These results are mechanism and cost evidence, not research-capability evidence.
- **Benchmark sealing.** The Codex sandbox limits writes, not reads. Contamination is detected by a full transcript audit, not prevented.
- **Bounded goal claims.** Compass goal claims are bounded by the declared grammar, synthesis bound and experiments (`UNIQUE_CLASS_WITHIN_SYNTHESIS_BOUND_ON_DECLARED_EXPERIMENTS`). `SEARCH_EXHAUSTED` speaks only about that bound.
- **RSI isolation.** RSI tools run in an isolated `python -I -B` subprocess with a step budget (`SUBPROCESS_ISOLATED_NOT_OS_SANDBOX`). This is not an OS sandbox.
