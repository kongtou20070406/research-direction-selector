# RDS 6.2.0

First stable release since 5.8.0. It carries the unpublished 6.0.0 and 6.1.0 work, described in their own notes
([6.0.0](6.0.0.md), [6.1.0](6.1.0.md)), and adds research notes, reminders and a research map. The exact revision
is named on the GitHub release.

## What is new since 6.1.0

- **One-command notes.** `note goal|expect|observe|attempt|claim|constraint` records one research fact as a row in
  the existing ledger. No new database, and `project init` still works afterwards.
- **State-triggered reminders.** `nudge` recomputes ten heuristic rules from the notes and asks one specific
  question, such as what repeated failures have kept fixed. Close a reminder with `nudge answer` and a later
  measurement, or `nudge dismiss` and a reason. Status is never stored.
- **Automatic delivery.** Host hooks deliver reminders and record attempts from shell results. Automatic notes
  keep a route name and outcome, never arguments or output. The hook never creates `.rds` and stays silent on errors.
- **Research map.** `map --output research-map.html` writes one offline page from notes and open reminders.

See [research notes](../research-notes.md).

## Compatibility

- Ledgers written at `6.0.0` stay readable, as do the versions listed in [versioning](../versioning.md). `6.1.0` was
  never written by the CLI and is rejected.
- Changing `VERSION` changes the source hash in `engine_id`, so an unchanged contract from an earlier checkout needs
  the existing new-contract path before further execution.
- From 5.8.0, the major version change is described under Era transition in [versioning](../versioning.md).

## Validation

- Full test suite at the candidate before the version commit, on Windows: 1 error, 50 skipped.
  The error is `test_symlinked_alias_is_the_same_root`, which needs a symlink privilege this machine lacks and fails
  the same way on the base commit. CI results for the release revision are on the merge pull request.
- The first full run of this branch found 33 failures and errors from this work, including a check that silenced hook
  status lines. All were fixed. Independent review by another model found 5 reminder-rule errors, reproduced and fixed.
- Two tests new in this branch were changed because they contradicted the older hook contract: on a non-ledger
  database the status line is now required, and the checks that nothing is written remain.
- Real host trials: Claude Code and OMP delivered reminders.

## Limits

- **Reminders are not shown to improve research.** In a preregistered comparison on jumpbench (162 trials), `state`
  minus `bare` du_auc was +0.040 and s_final −0.135, and `state` minus `sham` du_auc was +0.013, all missing the rule,
  so validation was not run. Intervals are wide, so neither gain nor absence of effect is shown. That test used four
  benchmark rules, of which two have `rds_nudge` counterparts, and did not test `expect_mismatch`, the ledger or the
  map. See [the result](../jumpbench/nudge-result-2026-11-01.md).
- Reminders are heuristics with assurance `RECORDED_INPUT_NOT_SCIENTIFIC_VERIFICATION`. A closed reminder is not
  evidence that anything is true, and `scientific_support` stays `UNKNOWN`.
- Codex hooks are registered and covered by packaging and protocol tests, but real delivery is unverified. Users must
  trust the hooks in `/hooks`.
- Automatic attempt recognition covers simple shell commands. Delivery reads the latest 2000 notes, so the start of a
  longer failure run is not visible and its reminder may repeat.
- Display polish to the older hypergraph viewer was reverted to keep its frozen bytes.
