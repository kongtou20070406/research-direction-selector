# RDS 6.3.0 - one research loop

An agent can now retain a research goal, explain why an approach is stuck,
propose a changed hypothesis/representation/decomposition, run an existing check
and receive the updated research context from the same command family.
The Skill makes this the ordinary research entry, with the CLI kept private to
the host agent. Existing specialized tools and campaign commands remain usable.

## Delivered behavior

- `research start/status/propose/check/advance/select/show` use existing
  ProjectStore notes and CAS. Parent routes, discriminating questions, scoped
  obligations, failures and original outputs survive restarts.
- Formal certificates, exact-math solver certificates and existing structure
  feedback are connected to this context. `research advance` uses the existing
  authorized candidate/verifier execution and recovery path.
- Checks replay originals; retries reuse recorded results. A changed observation
  requires an explicit revised proposal. Historical checks still replay after a
  goal change; new execution cannot silently use an older goal.
- Existing native-objective workspaces can add research notes in the same ledger.
  A working goal does not replace the frozen objective or activate TMS claims.
- The Skill now leads with a continuous research conversation and loads detailed
  campaign procedures only as needed. Existing OPEN Compass behavior is retained.

See the [loop guide](../research-loop.md) and the runnable
[public CLI example](../../examples/research-loop/run.py).

## Compatibility and installation

CLI, reference reader, Skill metadata and generated host manifests use 6.3.0.
This is an additive feature release relative to the 6.x checkout. Readable
6.0.0 and 6.2.0 ledgers retain their bytes, contract checks and engine admission
guards. The source/environment binding can still require the existing new-contract
path before execution; reading an old ledger grants no new execution permission.

The last previously published stable release was 5.8.0. This release also carries
the intervening main-branch work; consult the [6.0 generation transition](../versioning.md#era-transition)
and the earlier [6.0](6.0.0.md), [6.1](6.1.0.md), [6.2](6.2.0.md) implementation notes.
Their validation statements concern earlier revisions, not this release.

GitHub assets contain separate Claude Code, Codex and OMP packages. Unpack the
matching package and follow [host installation](../host-plugins.md). Packaging
and relocation tests do not prove real host hook delivery. No user installation
or trust configuration is changed by publishing these archives.

## Verification and limits

The [prospective protocol](../research-loop-protocol.md) covers a failed route,
changed representation, scoped success, restart/reuse, tampering and coexistence
with existing project state. Focused tests cover the real CLI, mathematical
checks and original empirical receipts. Independent review reproduced two
integration defects (historical replay and native-ledger entry); both were fixed
and independently reproduced again. The release's exact commit, complete-suite
results and CI links are recorded in the GitHub release and its verification
receipt. Host packages are also exercised after relocation.

The fixed-point example uses prescribed ideas, not autonomous discovery. The
host supplies the reasoning change; different text is not a semantic novelty
test. A checked obligation is not a certificate for an unspecified broader goal.
External observations remain INPUT_REPORTED, unavailable evidence stays UNKNOWN,
and `scientific_support` stays UNKNOWN. Research benefit is **UNMEASURED**; the
user explicitly deferred new efficacy experiments for this integration release.
