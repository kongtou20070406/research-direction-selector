# Research Direction Selector：开发与验收计划

文档导航更新：2026-10-10。产品愿景与验收问题见[愿景与范围](rds-purpose.zh-CN.md)（[English](rds-purpose.md)）：根本目的，是让 AI 更好地辅助人进行科研；RDS 是选择的实现形式，通过连接目标、证据、决策与执行来支撑研究者。

五个组件固定为 **Skill、执行与验收内核、研究状态与记忆、Advisor、RSI**。本页后续 M01–M10 保留 2026-09-30 的开发基线与验收要求；其中“当前缺口”、版本和回归计数是当时状态，不代表最新 main 的完整能力清单。[5.8 完整目标与协作计划](5.8-vision.zh-CN.md)（[English](5.8-vision.md)）同样保留提案时的范围与状态。实际入口按当前 checkout 的[命令图](command-map.md)核对。

自动化程度与历史自主分级用于描述手段和能力范围；本轮产品定位以对研究者的辅助价值为中心。

## 按愿景组织后续验收

| 推进方向 | 当前可用的工程入口 | 还需什么证据 |
| --- | --- | --- |
| 让证据决定下一步 | [程序持有的 Advisor](program-owned-advisor.md)、目标谓词与候选条件 | 未使用研究任务上，相同模型、工具和总预算的独立任务验收与决策比较。 |
| 失败后修订问题或方法 | [问题结构](problem-structure.md)、[有界研究推进](autonomy-loop.md) | 原失败、竞争修订、区分检验、原始结果，以及结果改变后续行动的真实研究轨迹。 |
| 中断后继续且少重复工作 | 回执、预算与[确定性接续](deterministic-continuation.md) | 原目标、花费、数据暴露、失败和人工介入可追溯的中断／恢复轨迹。 |
| 改善 RDS 自身决策策略 | [RSI 评估与采用](../references/rsi-evidence.md) | 未使用案例上的同总成本候选／基线比较，保留负面结果与回退依据。 |

这些入口说明已有工程连接，不替代相应科学验收，也不将开放 PR 或历史提案算成已交付能力。

## 目标：近期全环节 L2，长期 L4／L5

当前已有受限功能可对应 **局部 L2**。近期目标是让六个科研环节都有可用的自动化支持，同时由人保留研究方向、关键判断与科学结果的接受权。**“全环节 L2”是 RDS 的产品覆盖目标，不是新增级别**；它也不等于无人工判断的完整自主发现循环。

| 科研环节 | 要交付的 L2 支持 | 完成依据 | 对应工作项 |
| --- | --- | --- | --- |
| 明确研究目标 | 把人的目标整理成可检查的问题、指标、基线、数据资格与预算；列出矛盾和缺项。 | 人能确认原意，随后所有计划和收据引用同一版本；缺项不被擅自补成事实。 | M01、M06、M10 |
| 选择下一步实验 | 从真实证据和有限模板生成候选，列出竞争解释、结果如何影响下一决定与成本。 | 人能沿原始来源复核；观测或约束变化会改变候选；有用候选不因未知成本被虚假排序。 | M01、M02、M03 |
| 检查实验设计 | 自动核对干预是否可实现、control 是否兼容、指标能否回答问题及确认数据是否合格。 | 不可行干预、身份冲突、未满足前提和证据缺失均有对应拒绝或 UNKNOWN；人工判断保留身份。 | M01、M02、M03、M09 |
| 管理实验过程 | 接入真实执行器，跟踪配置、进程、日志、预算、失败成本和产物；支持中断恢复。 | 已授权任务能实际运行并产出绑定记录；超时、非零退出和缺产物不能冒充完成。 | M03、M04、M06 |
| 判断实验结果 | 计算任务指标、检查实际干预，把任务收益与机制支持分别报告，提出待人接受的结论。 | 评价器可独立重放；分数提高不能自动宣告机制成立；不足的观测保留未定。 | M01、M04、M07 |
| 积累并继续推进 | 保存已知条件、失败与理由，恢复研究现场，生成有依据的下一步候选。 | 换会话后不丢预算和数据暴露状态，不重复已完成运行；人能核对决定为何延续或改变。 | M02、M06、M10 |

近期完成时，每一环节都要有来自真实任务的产物和失败处理记录，并明确仍需人的判断。组件测试或示例界面只能验证相应组件，不能代替这张表的交付。M07 另行比较实际收益和总成本，不因环节齐全就宣布优于其他 skill。

长期以原框架的 **L4／L5** 为方向：前者涉及多个科研领域的闭环及有限自主设定目标，后者涉及全面自主科研。它们需要各自的新能力与真实研究验收，没有承诺日期；自动修改规则、自动停机或增加组件数都不能代替这些要求。先交付全环节 L2，再在明确领域检验 M08 的闭环；跨领域和开放目标留待该证据基础建立后推进。原级别含义按[公开版本 §5／Table 2](https://arxiv.org/html/2305.02251v2#S5)核对，正式刊载见[2026 期刊版](https://link.springer.com/article/10.1007/s10994-025-06955-2)。

## 开发顺序

当前优先体验与实用：先在一个真实项目里减少重复解释背景、翻找记录、核对结果和纠正 AI 的工作，再扩大自动化覆盖。横向 skill 比较暂缓；已查的公开 benchmark 只保留为后续选型资料，不启动比较实验。

| 顺序 | 工作项 | 主组件 | 完成后得到什么 |
| --- | --- | --- | --- |
| 第一批 | M01 真实证据接入；M06 接续恢复；M10 真人查看与核对 | Advisor、记忆、工作台 | 读入已有记录，不反复解释背景，下一决定能指回真实产物。 |
| 第二批 | M02 实验候选组合；M03 成本与对照复用；M04 单项目执行适配 | Advisor、内核 | 候选能实际执行，兼容的已完成工作能复用，失败不会丢现场。 |
| 扩大自动化前 | M05 规则采用门禁；M08 受限科研闭环与范围验收 | RSI、内核、Skill | 规则升级和自动接续有独立依据，越界或故障有可检查的处理。 |
| 随需求推进 | M09 Lean4/mathlib 协作 | 内核、Skill | 为实际需要的数学子任务复用已有证明生态。 |
| 暂缓 | M07 同类 skill 对比 | 评测 | 只保留选型资料；真实项目体验稳定且重新确定投入后再考虑。 |

这是依赖与优先顺序，不是完成日期承诺。M01–M06 已有上表列明的首版范围；下面保留完整目标及原始缺口，超出首版范围的真实科研验收仍待完成。

## M01 · 把原始实验记录接到 Advisor

**原始缺口（v5.5.0-rc.2）：** `cmd_advise` 可以读取账本，但图搜索的 facts 和 costs 仍主要由 `--research-context` 提供；来源检查只要求有来源标记，不自动读取文件、核验运行收据或对齐训练协议。

**怎么做：**

1. 先支持本地配置、CSV/JSON 指标、原始日志及 RDS 收据四类输入；用有限格式适配器读取，不先做任意文本的自动科学解释。
2. 将每个事实绑定到文件哈希、字段/行位置、run ID、代码与配置版本、数据分区和指标定义。声明值、直接观测、程序推导、未知分别保存。
3. 推导事实同时保存输入 IDs、计算方法和适用条件。收据、配置、日志不一致时输出冲突，不选一个较好看的值。
4. `--research-context` 保留为人工输入入口；人工声明不能自动取得执行器观测的身份。

**交付物：** 版本化输入 schema、只读导入器、CLI 接入、事实来源清单和缺证据报告；主要改动位置为 [Advisor 搜索](../scripts/rds_advisor_search.py)及 [CLI](../scripts/rds_cli.py)。

**通过什么：** 用完整记录、缺日志、错 run ID、被改写文件、不同 metric reduction、错误数据分区和自签成功字段等独立输入验收。每条导出事实必须可回到原始位置；冲突和缺失不能变成已观测。文件哈希通过只说明身份一致。

## M02 · 从条件组合走到实验候选组合

**原始缺口（v5.5.0-rc.2）：** 搜索已能组合前置条件，但每个节点主要返回人写好的 `executable.action` 或 `on_false`；没有从多种实验部件构造新实验的通用程序。

**怎么做：** 建立有限、版本化的实验模板：干预对象、允许取值、保持不变项、control、测量、竞争解释、不同结果对应的下一决定、成本和停止条件。按类型与前提枚举兼容组合，以 intervention fingerprint 去重；设置组合数和深度上限，并报告截断。模型新提案先变成待审模板，不能跳过检查直接执行。

**交付物：** 模板 schema、兼容性检查器、候选枚举器、候选→规则→事实推导记录，以及至少两个不同类型的干预模板。先接入已获证据支持的模板，不以补齐 23 个节点为唯一目标。

**通过什么：** 保留独立案例，检查干预是否真的改变目标属性、互斥部件能否被阻止、control 是否匹配、重复组合是否去重、条件变化是否改变候选。解释的预测未知或重叠时保留多个解释；不编造成功概率或信息增益。完整科研收益另由 M07 测量。

## M03 · 用真实增量成本和兼容对照选择实验

**原始缺口（v5.5.0-rc.2）：** 图搜索已支持可比成本，但费用来自输入；公开组件挑战测的是本地元数据读取，不能用它估计训练。现有标量缓存也不等于随机训练模型的通用 control cache。

**怎么做：** 从已完成运行收集训练、评价、恢复、诊断和失败尝试的成本，分别记录 GPU/CPU 时间、调用费用及需要的人工工作；缺项保留未知。扩展训练对照复用时核对代码、数据/分区、初始状态、seed、checkpoint、schedule、sample-work 和数值协议。按同一资源预算比较；不同单位不能直接相加成一个“便宜分”。

**交付物：** 成本采集适配器、资源预算向量、训练 control 的身份检查与失效原因、包含失败尝试的总成本报告。

**通过什么：** 用代码变化、checkpoint 变化、相同 seed 但不同随机路径、数据变更、评价开销遗漏、零预算、未知成本和并发预留验收。重复的已完成兼容 control 能复用；不兼容或身份未知不能当成命中。没有观察到会改变决策的 seed 不稳定性时，不追加多 seed。

## M04 · 接入一个真实研究项目的执行器

**原始缺口（v5.5.0-rc.2）：** 参考内核执行受限标量 AST；它没有替真实训练器执行 PyTorch 研究，也不能用参考收据认证外部训练结果。

**怎么做：** 为已有项目定义最小 runner adapter：锁定代码、配置、数据、评价器与允许命令；记录启动、运行、退出和产物。先在 CPU 任务验证进程与产物协议，再接已授权的真实训练器。需要跨会话继续的 Windows 长任务由 Task Scheduler 托管，记录本工具启动的任务 ID、日志及恢复入口。

**交付物：** 项目适配器、运行 manifest、原始日志、配置/产物清单、实际成本和完成收据；保持 run status、task gain、mechanism 三条判断独立。

**通过什么：** 覆盖成功、超时、非零退出、产物缺失、评价器被替换、启动后配置变化、进程中断和恢复。仅有 exit code 0 不能宣布科研成功；未发生声明干预不能支持机制结论。运行与确认使用同一锁定协议，并计入失败开销。

## M05 · 给 RSI 加上真正的规则采用门禁

**原始缺口（v5.5.0-rc.2）：** 当前 `evaluate_rule` 主要做结构检查，评估案例数为 0；`meta apply-rule` 验证结构后即可写入图。候选修复或 lint 通过不能说明科研策略改善。

**怎么做：** 将提出、评估、采用分成三个阶段。候选记录来源、适用范围、反例、旧/新版本；先检查图结构与兼容性，再在未用于提出修改的案例上回放。采用报告明确比较对象、预算、信息暴露、改变的决定与失败项；写入前验证报告绑定的是同一个候选版本。保留原规则和回退入口。

**交付物：** 隔离候选目录、案例执行器、比较报告、绑定检查、采用/拒绝记录及回退命令；修改 [规则管理](../scripts/rds_meta.py)相关路径。

**通过什么：** 案例数为 0、只有训练案例、报告被改写、规则与报告版本不匹配、循环依赖和资源越界均不能被标为评估通过。政策收益要在等总成本研究轨迹上测量，不能用结构回归通过数或模型自评分替代。RSI 与 L1–L4 自主程度分开验收。

## M06 · 可靠恢复研究现场

**原始缺口（v5.5.0-rc.2）：** Obelisk 检索和执行账本都有基础，但“恢复后与中断前作出同一合理决定”的跨会话链路尚未形成独立验收。

**怎么做：** 在决策边界保存问题、目标/指标、已花费与预留预算、候选及其理由、未决证据、运行 ID 和产物位置。恢复时先读实时状态，再按项目范围检索真正相关的历史；发现新旧记录冲突就列出冲突。使用现有 Obelisk，执行账本不保存另一份完整聊天镜像。

**交付物：** 可恢复的决策 checkpoint、恢复摘要、原始依据链接和运行状态对账。

**通过什么：** 在预留、运行、完成但未验收、预算耗尽四个边界中断并恢复；不得重复启动已在运行或已完成的实验，不得重置预算，不得恢复暴露数据的独立确认身份。历史文本不能产生新授权。

## M07 · 测量 RDS 相对其他 skill 的真实增量

**状态：暂缓。** 当前先做真实项目的体验与实用性，不安排本项比较执行。以下保留已有选型，供以后重新决定是否投入。

**当前缺口：** 现有 8 个公开任务改编案例是组件检查；没有同模型、同任务、同预算的 skill 对比成绩。

**以后若恢复：** 可先采用 SkillsBench 的 CPU 科研分析任务，固定底座模型、运行框架、数据、通用工具和总预算，比较无额外科研 skill、K-Dense 假说生成/批判性思维、RDS 完整组件。Orchestra 头脑风暴适用于方向建议子测，按它的声明范围评价。skill 自带工具的成本也计入。原题验收与额外的证据/建议审核分别报告。

**已保留资料：** [benchmark 选型与暂缓方案](benchmark-plan.md)。恢复后才准备实际版本清单、隔离任务环境、预先声明的指标、逐题产物与失败记录、费用和耗时。

**通过什么：** 原任务 grader 能验收真实产物；评测代理看不到 oracle/隐藏答案；每个条件资源口径一致。先每个不同任务各跑一次，逐题公布结果；不声称统计稳定领先。完整科研闭环优先考虑 ResearchGym，确认执行环境与预算后再运行。新分数取得前不改写 README 为已领先。

## M08 · 按已有自主分级验收限定领域的科研闭环

**当前缺口：** 已有契约、账本和受限执行模块，但没有真实研究中“提出/选择假说→设计→执行→分析→更新下一步”的完整自主轨迹。旧代码中的 `L3` 是历史工程标签，不能证明论文定义的 L3。

**怎么做：** 直接采用 Kramer 等（2026）的科研自主框架，不自行重定义级别。先围绕其限定领域闭环要求展开：固定一个问题空间和允许干预，接通 M01 的证据、M02 的候选与 M04 的执行；分析结果后更新可检验假说和下一决定。单独定义 RDS 的运行约束：数据与评价器、允许动作、资源上限、退出/恢复条件和何时需要人提供缺失判断。异常时保存现场并停止未授权的推进。

**交付物：** [原框架及 RDS 对应范围](research-autonomy.md)、真实闭环轨迹、范围检查、人工介入记录、停止/恢复记录，以及各适配器的能力清单。

**通过什么：** 检查每一轮的假说、实际干预、原始结果及下一决定能否相互追溯，并记录哪些步骤仍依赖人。注入缺文件、未知工具、协议漂移、不可行任务、预算不足和执行器失联；不得扩大授权或补造结论。完整闭环、科学收益、故障处理和规则改进分别验收。原框架的 L4 还涉及多个科研领域与有限自主设定目标，单领域闭环或自动停机不能满足它；跨领域研究不是本批工作范围。定义来源见[公开版本 §5／Table 2](https://arxiv.org/html/2305.02251v2#S5)，正式刊载见[期刊版 §5／Table 5](https://link.springer.com/article/10.1007/s10994-025-06955-2#Sec5)。

## M09 · 复用 Lean4/mathlib 扩展数学子任务

**当前缺口：** 原生 Lean 接口只支持固定模板的闭合有理数关系；Python 领域证书覆盖较多声明，通用 mathlib 深度学习模型翻译尚未实现。

**怎么做：** 从一个明确的模型/性质对开始，例如有限 Linear/ReLU 的区间性质。定义模型语义与性质 IR，优先引用 Lean4/mathlib 已有定义和定理，生成有边界的义务并由真实 Lean 内核检查。单独说明精确有理模型与实际浮点运行的对应条件；不重造 Lean 推理系统。

**交付物：** 一个模型/性质适配器、固定 Lean/mathlib 版本、生成的声明与证明、源码与运行器绑定、独立重放和资源限制。

**通过什么：** 正确与错误实例、维度/参数改写、不支持算子、超时和证书篡改均有明确结果；未知保持 UNKNOWN。证明必须对应声明，不能用 tactic 名称、元数据通过或 Python certificate 冒充原生 Lean 证明。数学性质成立仍不代替真实干预和任务收益。
