## 2. 纲领 L1：表示层（反统一 → MDL 入库 → 复用）

### 2.1 反统一的输入与输出

**输入（两个来源，优先级 a > b）：**

a. **oracle 认证过的成功**：`TOOL_QUALIFIED` 事件的 `oracle.known_positive.law_ast`（`rds_compass_rsi.py:407`）+ 工具 `source` 本身。它过了 holdout + mutant + witness 三元组，是带反例见证的成功。
b. **jump 采纳的 patch**：`HYPOTHESIS` 事件中 `origin` 以 `jump:jNN:` 开头（`rds_compass.py:1101`）的 `predict` AST，特别是 `PULSE_PATCH`（ite 结构，`rds_compass.py:723-726`）与 `RESIDUAL_CORRECTION`/`REGIME_SPLIT` 模式的 fit。它只过了 replay + equivalence 过滤器，证据等级低一档，但模板化价值最高（稀疏脉冲、分段是现枚举器明确缺的能力）。

跨 campaign 的来源是 library record：注意 `export()` 目前只存 `qualification.law` 文本（`rds_compass_rsi.py:515`），**第一刀要在 library record 里补 `law_ast` 字段**（schema 加版本号 `rds-compass-tool-v2`，v1 记录按无 ast 降级处理，不修复、不报错——沿用 damaged-record 跳过语义，`rds_compass_rsi.py:287-288`）。

**反统一算法**：在 model 的 dict-AST（`{'op':..., 'args':[...]}`）上做一阶反统一（Plotkin 最小泛化，lgg）：op 与 arity 相同 → 递归 args；否则 → hole，记录置换对 (σ₁, σ₂)。hole 分三类：`CONST`（具体常数，带取值集合）、`VAR`（变量名映射）、`EXPR`（任意子表达式，带节点数上限）。

**输出**：参数化算子模板——
```json
{"schema": "rds-compass-operator-v1",
 "template_ast": {"op": "ite", "args": [{"op":"eq","args":[{"var":"$V1"},{"const":"$C1"}]}, {"const":"$C2"}, "$E1"]},
 "holes": [{"name":"$V1","kind":"VAR"}, {"name":"$C1","kind":"CONST_INT"}, {"name":"$C2","kind":"CONST_RATIONAL"}, {"name":"$E1","kind":"EXPR","max_nodes":15}],
 "support": [{"ledger_root": "...", "record_sha256": "...", "law": "..."}, ...],
 "mdl": {"template_bits": 0, "residual_bits": [0, 0], "standalone_bits": [0, 0], "ratio": 0.0},
 "domain_signature": "..."}
```
实例化 = 用 support 案例的 σ 回填 holes，产出合法的单参数 source 或 derived 表达式。

**两个真实样例**（devset 里就躺着）：I.12.1 `(mu*n)` × I.14.3 `((h*m)*g)` → 单项式模板 `(* $E1 $E2)`；sparse-mid 型 pulse × PULSE_PATCH 产物 → `ite(eq($V1,$C1), $C2, $E1)`。

**消费方式**（两种，都算「入库」）：
1. 作为 `derived` 项注入 `synthesize()` 的 `derived` 参数（参数已存在，`rds_compass_model.py:784`；`_fits` 的 pairwise 派生 :676-684 就是这个机制的手工版）；
2. 实例化为单参数整数 source，走现有 `evaluate_tools` + oracle triple 全路径。

### 2.2 MDL 入库判据

编码口径（写死，防口径漂移）：
- AST 节点 = 1 字节 opcode（算子集封闭，`rds_compass_model.py:33-38` 共 ~30 个）；整数常数 Elias-gamma；有理数 = 两个 Elias-gamma；变量 = ⌈log2(nvars)⌉ bit。
- `L(law)` = 上述位长。粗粒度代理可用现有 `model.size()`（节点数），但入库判定用位级编码。

压缩率：
```
R = Σᵢ L(lawᵢ 单独存储)  /  ( L(template) + Σᵢ L(σᵢ 残差) + L(support 表) )
```

**入库阈值：R ≥ 1.5 且 support ≥ 2 且「模板非平凡」。** 理由：
- support = 1 时 R 按构造恒 > 1（模板=案例本身 + 零残差），无泛化证据，必须排除；
- R ≥ 1.5 = 至少省 1/3 编码，对应「模板泛化后残差很小」——常数位置、变量绑定都稳定；
- **模板非平凡（必须同时满足）**：把模板按某个 support 的 σ 回填后，结果与**至少一个**其他 support 案例的 AST 不等价。若模板回填后对每个 support 都只能重建成原案例（模板没吸收任何结构差异），它只是把案例重写了一遍，泛化度为零，不入库；
- 附加硬条件：模板用任一 support 的 σ 实例化后节点数 ≤ `MAX_RULEBOOK_NODES=64`，且（若作为工具）实例化产物过 `extract()` 的 allowlist（`rds_compass_rsi.py:140-149`）。

> 「模板非平凡」是本节新增的唯一判据，代价是一次 AST 比较，换来挡掉「R 虚高但零泛化」的假入库。没有它，两个形状相同的案例会产出一个对任何新案例都只能回填成已知答案的模板。

**入库 = offer，不是证书。** 算子只影响枚举顺序与 pool 排位（L2 消费），资格判定仍是 oracle triple。误入库的算子最坏后果是浪费一次 runner 调用——fail-closed 语义不被 MDL 绕过。

### 2.3 沙箱契约测试的自动生成

每个模板入库时自动生成并持久化 `contract` 字段：

1. **见证重放**：对每个 support 案例，取其 `boundary.declared_candidates` 全集输入（`rds_compass_rsi.py:506`），模板实例化后过 `evaluate_tools`，要求输出与该案例 receipted values 逐点一致（Fraction 字符串相等）。
2. **边界探针**：domain min/max、0、±1，以及首个越出 declared 范围的点——要求每个输入要么返回 int/Fraction、要么 None（即沿用 `UNDEFINED_ON_DECLARED_DOMAIN` / `OUTSIDE_EXACT_DOMAIN` 的判定式，`rds_compass_rsi.py:475-476`），禁止抛未捕获异常。
3. **可判别性**：实例化的 `mutants()`（确定性生成，`rds_compass_rsi.py:168-193`）中至少 1 个在见证输入集上与模板取值不同——防止常量退化模板入库。
4. **预算**：契约测试在 runner 60s 墙钟 + per-input STEP_LIMIT 内完成；任一不过 → 模板不入库，记一条离线日志（不进 campaign ledger）。

复用时先重跑契约（秒级，输入集小），再进 oracle triple——契约是 cheap pre-filter，oracle 是证书，两层不合并。

### 2.4 向量化求值器替代 `sys.settrace`（保留 per-input bound）

问题：settrace 每行一次 Python 回调，帧开销 6-47×（fa2dce6 的实测数字）。但 **per-input counter 是命根子**（b653810）：任何替代方案若让单输入跑飞拖死整批，直接判死。

**推荐方案：AST 级受限解释器（不再 exec）。**
- tool source 经 `extract()` 后已有 AST；用白名单递归求值器逐节点解释，**每求值一个节点 `steps[0] += 1`，per-input 独立计数器**，超限 raise `Budget` → 该输入值 None，继续下一输入（与 RUNNER :77-79 语义逐条对齐）。
- 白名单节点 = `families()` 30 原语实际用到的闭集：FunctionDef/Return/Assign/AugAssign/If/While/Compare/BoolOp/BinOp/UnaryOp/Name/Constant/Call{abs,int,sum,all,range,max,min,len}/For-range/math.{isqrt,sqrt}。其余节点（Import 非白名单、Attribute 越界、Subscript、Lambda、Try 等）**parse 期拒绝**，fail-closed。
- **step 语义切换必须重新校准**：settrace 的 step ≈ 行/调用，解释器的 step = AST 节点求值，两者不同量纲。切换流程：影子模式跑全部 30 原语 × devset 输入，统计解释器 step 分布，新 `STEP_LIMIT` 取 P99.9 × 2；值向量与 settrace RUNNER **逐字节相等**才切换（同输入同输出是硬等价）。
- **回归测试铁律**：必须含「单输入死循环（`while True: pass`）→ 该输入 None、同工具其余输入正常、同批其余工具正常」——即 fa2dce6 红的 6 条的等价物。关掉新逻辑旧行为原样（最小反向测试）。

**等价口径必须写死（b653810 的直接教训）：** 「逐字节相等」不能只说，要说清比的是什么。

| 项 | 口径 |
|---|---|
| 输入集合 | 全部 support 案例的 `declared_candidates` 全集（不是抽样），加 domain 边界 ±1 个越界点 |
| 输出比较 | 每个输入上 `Fraction` 字符串精确相等；异常情形两边都是 `None` 且 `reason` 字段相同 |
| 覆盖范围 | 30 原语 × 上述输入集，**100% 逐点相等**才算通过，不容许任何容差 |
| 死循环用例 | 单输入超限 → 该输入 `None`；同工具其余输入值**逐点与 settrace 版相同**；同批其余工具全部正常 |
| 切换前置 | 上述五项全过 + 影子模式跑满一轮 devset 15 cells 结果逐字节相同 |

这张表不写死，第 5 步就会重演 fa2dce6：声称「安全机制移到别处」，而那个「别处」不成立。

被否决的替代：
- per-input subprocess：48 工具 × 25 输入 ≈ 1200 次进程创建，Windows 上每次 ~100ms 起步，总开销反超 settrace。否决。
- 父进程 per-input wall counter（b653810 教训里的「parent 真加 counter」合规版）：父进程只能按墙钟杀，杀的是整批子进程，丢整批值——除非把批切成 per-input 批，退回上一条。否决。

第一刀**不做**向量化（正确性影子先行是第二刀），L1 第一刀复用现有 RUNNER。

### 2.5 L1 第一刀（最小端到端路径）

**路径：离线反统一 → 算子入 library → 在线零改动复用。**

1. 离线脚本（新文件，不在本方案范围改代码）读 N 个历史 campaign 的 `.rds` ledger，收集 2.1(a)(b) 两类成功 AST；
2. 按 `domain_signature`（见 3.1）分桶，桶内做 lgg 反统一；
3. R ≥ 1.5 且 support ≥ 2 且契约测试通过 → 写 library record（`rds-compass-tool-v2` schema，create-only，provenance 指向各 support 的 origin ledger）；
4. 在线侧**零改动**：`library_tools()` 已把 library record 排进 pool 最前且 ORIGIN_VERIFIED 优先（`rds_compass_rsi.py:296,440-444`），下一个 capability gap 自然消费；资格仍由 oracle triple 独立判定。

明确不做（第一刀）：不改 `decide()`、不改 `synthesize` 内核、不动 RUNNER、不支持多参数工具（`:144` 约束保留，模板实例化必须产出单参数函数）、不做实时（in-drive）反统一——反统一全部离线做，drive 内只消费库。

## 3. 纲领 L2：先验路由层（P(operator | domain_signature, residual_pattern)）

### 3.1 domain_signature 与 residual_pattern 的提取

**domain_signature**（静态，DECLARED 事件定型）从 `plan` 提取：
- inputs 个数、各输入 `integer` 标志、各输入 (max−min) 跨度的 log10 分桶；
- goal observable 的 tolerance 类型（abs=0 / rel=0 / 非零）；
- `grammar.operators` 排序后的集合 sha；
- candidates 数量分桶。

组成 canonical dict 后取 `digest`（复用 `rds_project.canonical/digest`，与 ledger 同口径）。库匹配先按 digest 精确命中；无命中退化三档桶：`{整数单变量, 整数多变量, 含实数}`。含实数桶**空先验、不路由**（fail-closed：数论原语在非整数域上无意义，`docs/compass.md:141` 已明说）。

**residual_pattern**（动态，每次 decide 重算，全部来自已 fold 的 state，零新测量）：
- `basin()` 的 streak 与 residuals（`rds_compass.py:322-346`）；
- live leader 的 `replay.counterexamples` 残差向量 → `log2(|residual|/tolerance)` 四桶直方图（**用容差归一**，换尺度后桶位不变，跨 campaign 可比）；
- 残差随主输入排序的符号模式（递增/递减/平坦/不可判）；
- `_since_jump` 的观测增量与 PROBE 计数（:282-284）。

这些量全部已有或可从现有字段一次推导，不需要新测量、不需要新事件。

### 3.2 条件先验的冷启动

**不用均匀分布。** 30 原语均匀先验（每个 1/30）与历史 qualification 率差一个量级，均匀先验 = 向路由注入假信息。三层 fallback（逐层退化，每层都 fail-closed）：

a. **library 统计**：扫描 library 目录全部 record + `origin_status()`（`rds_compass_rsi.py:256-270`），按 domain_signature 桶统计各算子/原语的 offer→QUALIFIED 转化率，拉普拉斯平滑 (k+1)/(n+2)。retracted 计入分母不计分子。
b. **桶内无数据 → 账本统计**：从现有 campaign ledger 的 `TOOL_QUALIFIED` 事件按 name 统计频率，归一化；整数单变量桶可用，其余桶跳过。
c. **完全无库 → 现状顺序**：pool 顺序保持 library → offers → catalogue（`rds_compass_rsi.py:444-445`），先验不发声。**先验永远只排序、不准入**：oracle triple 是唯一的资格判据，先验误判的最坏代价是 pool 内排序次优 + 一次 runner 调用。

学条件先验的更新（上线后）：每次 `TOOL_QUALIFIED` / `TOOL_REJECTED` 事件都是一桶一次伯努利试验，按 (signature 桶, tool sha) 做 Beta 后验更新；后验只影响排序。注意 `TOOL_REJECTED` 要按 reason 分层：`ORACLE_NON_DISCRIMINATING`/`HOLDOUT_REFUTED` 是真负例，`TOOL_RUNNER_TIMEOUT` 是基建噪声不计入。

### 3.3 VoI Router 触发条件

**「边际 EIG 率低于阈值」的可操作化**（两档，第一刀只做 A）：

- **触发点 A（硬枯竭）**：`decide()` EXPERIMENT 分支（`rds_compass.py:492-504`）里 `ranking['ranked']` 为空——全部候选被 ALREADY_OBSERVED / NON_DISCRIMINATING / EQUIVALENT_PARTITION 排除。这就是边际 EIG = 0 的精确定义：**再买任何点都买不到区分度**。现行为是静默 fall through 到 RIVALS/CONFIRM（:506-511）——花钱买零信息，或重复已试过的 RIVALS。这是路由唤醒 LLM 的第一触发条件。
- **触发点 B（软低值，第二刀）**：ranked 非空但 `top['eig_per_cost'] < τ`。τ 用**相对口径**：τ = 0.1 × 本 campaign 既往 EXPERIMENT 决策的 `eig_per_cost` 中位数（该字段已存进 DECISION 事件，:501）。相对阈值对最小 devset 也成立，绝对阈值不注册。

**发什么事件：不发明新事件类型。** 路由判断把 EIG 枯竭视为等效 basin trigger，直接走现有 `escape()` 全路径（`_fits(escalate=True)` → RSI → packet → `PROPOSALS_REQUESTED`），`JUMP` 事件的 trigger 字段记：
```json
{"trigger": "LOW_MARGINAL_EIG", "ranked_total": 0,
 "excluded": [{"id": "...", "reason": "NON_DISCRIMINATING"}],
 "top_eig_per_cost": null, "median_eig_per_cost": 0.42}
```
语义与 `docs/compass.md:102` 一致：「the agent is asked exactly when Compass's own bounded search has nothing」——EIG 枯竭正是「买点无用」意义上的 nothing。ESCAPE 而不是 PROPOSALS 新事件，因为 escape() 已经处理了 agent 缺席（NO_RIVAL_WITHIN_BOUND）、token 预算 fail-closed（:1042-1043）、STALE_RESPONSE 等全部边角。

**防抖动**（照搬 `_barren` 语义，:431-440）：同一 observations 计数下 LOW_MARGINAL_EIG 最多触发一次；触发后 NONE_ADOPTED 则须 ≥1 个新观测才可再触发；每次触发消耗 `escape.max_jumps`（默认 6）的同一计数——路由与 basin 共享 jump 预算，router 不可能把 campaign 变成 LLM 循环；jumps 用尽 → SEARCH_EXHAUSTED 语义不变。

### 3.4 与 `decide()` 的集成点

精确插入位置：`rds_compass.py` 的 EXPERIMENT 分支内，`ranking = model.rank_experiments(...)`（:495-497）算完之后、`if ranking['ranked']: return EXPERIMENT...`（:498-504）之前：

```
ranking 算完（成本已付，不重复计算）
  ├─ ranked 非空且 top.eig_per_cost ≥ τ → EXPERIMENT（现状，不动）
  ├─ ranked 为空或 top < τ:
  │     ├─ 声明了 agent 且 agent_tokens == AVAILABLE 且本证据计数未触发过
  │     │     → return {'action': 'ESCAPE', 'basin': {**diagnosis, 'trigger': 'LOW_MARGINAL_EIG', ...}}
  │     └─ 否则 → fall through（现状 RIVALS/CONFIRM，不动）
```

为什么插在这里而不是 `basin()`：basin() 是纯残差/streak 诊断，不算 outcome partition；EIG 需要 live rivals 的划分，只有 EXPERIMENT 分支付了 `rank_experiments` 的成本。插在这里**零重复计算**。rows < 2 的情形已被 basin 的 NO_RIVALS/ALL_REFUTED 覆盖，不需要路由。

与预算的关系：`can_buy` 判定在前（:459），EIG 枯竭触发 ESCAPE 不买实验点，只花 agent tokens（受 `agent.max_tokens` 的 AVAILABLE/EXHAUSTED/USAGE_UNREPORTED 闸，:1042-1043 + `docs/compass.md:108-112`）。DECISION 记录照旧一条（drive 每步一条），路由信息进 `reason`/`basin` 字段，**事件条数与现状同量级**：一次触发 = 1 JUMP + 1 DISPOSITION（+ 可能若干 HYPOTHESIS），max_jumps=6 封顶 → ≤ 12 条额外事件，对 MAX_EVENTS=20000 无感。

### 3.5 L2 第一刀（最小「枚举 EIG 率低 → 唤醒 LLM」路径）

只做：触发点 A（ranked 为空）+ 冷启动 (c)（不排序，纯路由）+ JUMP trigger 字段扩展。

**入口前置修正（核实后新增，必读）：** `decide()` 的 EXPERIMENT 分支门是 `if len(rows) >= 2 and can_buy:`（`rds_compass.py:492`）。**单存活假设（`rows == 1`）根本进不了这个分支**，`rank_experiments` 从未被调用，触发点 A 在 `rows == 1` 时永远不会发生。

而 `rows == 1` 正是 EIG 枯竭的最典型形态：只剩一个假设，任何新点都买不到区分度。`feynman-I.6.20a` 三档一路 SEARCH_EXHAUSTED，很可能就是在多假设阶段把预算烧光了，进入 `rows == 1` 之后彻底失去路由入口。

所以第一刀必须包含一条**入口放宽**：把 `rows == 1` 纳入路由判定，但**不改 `rows == 1` 时现有的 EXPERIMENT 行为**（现状本就不买点）。具体形态：

```
if len(rows) >= 2 and can_buy:            # 现状，不动
    ... ranking ...
if len(rows) == 1 and can_buy:            # 新增：单存活假设的枯竭判定
    # 不调 rank_experiments（无第二假设可区分，EIG 恒为 0）
    # 直接判定为 EIG 枯竭，满足下列全部条件才路由
    → DECIDE_RANKED_SINGLE
```

`rows == 1` 的枯竭判据（全部满足才触发，缺一不触发）：

1. `not diagnosis['trigger']` —— basin 已经拉响的路走原 ESCAPE 分支，路由不接管；
2. `can_buy` 为真（还有实验预算，并非预算耗尽）；
3. 本证据计数下未触发过（防抖，与 `_barren` 同语义）；
4. 声明了 agent 且 `agent_tokens` 为 `AVAILABLE`。

不触发时**逐字节 fall through 到现状**（RIVALS/CONFIRM）。这条放宽是纯加法，任何一条不满足就走老路。

不做的：τ 软触发、Beta 后验排序、domain_signature 精确分桶、operator 级的 synthesize 加权（那是把先验灌进枚举器内核，留到 L1 库有数据之后）。

观测口径（drive 日志可机械提取）：LOW_MARGINAL_EIG 触发次数、触发后 ADOPTED/NONE_ADOPTED、触发前后 bought 点差。

## 4. 可证伪信号（预注册口径）与帕累托门禁

### 4.1 L1 可证伪信号

**预注册（跑前写死）：**

- 主指标：`claim_exact` 单元格数（15 cells = 5 方程 × B∈{8,16,32}，devset-run.md 口径：GOAL_IDENTIFIED 且全 rows 重放 0 反例，PARTIAL_FIT 不计）。
- 对照：同一 `devset_run.py`，L1 off（library 清空）vs L1 on（注入反统一算子库）。复现命令各一条，结果落盘 JSON。
- **判定（四条，全部为门槛）：**
  1. `claim_exact(L1 on) ≥ claim_exact(L1 off)`，且**任何 cell 不得由 ✓ 变 ✗**；
  2. **复用证据**：`claim_exact` 严格提升，或 15 cells 的实验数总和严格下降——两条满足其一；
  3. **成本约束**：15 cells 的实验数总和 ≤ 1.25 × 基线总和（质量提升也不许无限换成本，口径沿用仓库合并门槛的 1.25×）；
  4. **安全项**：任何 cell 不得新增假认证（GOAL_IDENTIFIED 但全 rows 重放有反例）。
- **附加成功（单独记，不作门槛）**：`feynman-I.6.20a` 任一 B 档从 SEARCH_EXHAUSTED 转为 GOAL_IDENTIFIED，或实验数下降。

> **为什么门槛 2 不写成「至少一个 cell 的实验数下降」（2026-10-20 修订）**：基线实测 15 cells 里 12 个 exact cell 的实验数**全是 4**（`benchmark/newtonbench/results/devset-run.json`），已经触到该 verifier 的最小覆盖；唯一有下降空间的 `I.6.20a`（8/14/14）又被本条降为附加。更要紧的是「实验数下降」只在**预算饱和**的 campaign 里才是「算子被复用」的有效代理——这四个方程在 B=8/16/32 下都只花 4 次，压根没买过探索，算子让合成更快也不会让实验数变少。拿一个在目标 regime 上没有杠杆面的指标当绝对门槛，跟 `_gap_wide_enough` 那次是同一个错误：判据看着合理，测出来恒为零，然后被误读成「改动无效」。

> 为什么把 I.6.20a 从门槛降为附加：它需要 `exp(-θ²/2)/√(2π)`，π 是无理常数。反统一能否产出含 π 的模板，取决于现库里是否存在可拆分的成功案例——这在跑之前是未知的。拿一个「上游数据是否存在」都不确定的条件当门槛，会让 L1 的成败取决于运气而非设计。门槛只认「算子被复用且不伤质量」。
- 次指标：关闭同一 gap 的 runner 墙钟中位数（给第二刀向量化求值器用）。
- **判负条件**：库注入后 15 cells 行为逐字节相同（算子零复用）→ L1 通路不存在，判负，写 LESSONS。
- 反向测试：library 清空后行为与注入前逐字节一致。

### 4.2 L2 可证伪信号

**预注册：**

- 主指标：成功 claim cells 的 bought 点中位数（experiments = EXPERIMENT+PROBE+CONFIRM+HOLDOUT）。**门槛：router on 不增（±0）**——路由不许把已收敛的 campaign 变贵。
- **通路存在性（门槛）**：15 cells 中 `LOW_MARGINAL_EIG` 触发总次数 ≥ 1，且触发后 6 个 jump 预算内出现至少一次非 `NONE_ADOPTED` 的 jump。**不指定是哪一档**——触发覆盖哪一档细胞由引擎决定，不由协议指定。I.6.20a 若触发就单独记录。
- 误唤醒率上限：触发后 `NONE_ADOPTED` 且后续 5 步内无新 `HYPOTHESIS` 的比例 ≤ 50%（超了说明触发口径太松，回滚到仅 basin trigger）。
- 硬门禁：`claim_exact` 不降；任何 cell 不得新增假认证（GOAL_IDENTIFIED 但全 rows 重放有反例 = 立刻判死整层）。

> 为什么不再点名 I.6.20a：与 4.1 同理。点名一个方程当门槛，等于让 L2 的成败取决于「那一个方程恰好走到 `rows == 1`」这个时序偶然。门槛认结构，附加认个案。

### 4.3 帕累托门禁（LCB 落地）

两维：质量 q = claim_exact 率（per-cell 二项）；成本 c = bought 点 / campaign（成功 cells 中位数）。

- 质量下置信界（单侧 95%，z = 1.645）：`q_LCB = q̂ − 1.645·√(q̂(1−q̂)/n)`；q̂ = 1 时用 rule-of-three 修正 `q_LCB = 1 − 3/n`。
- 成本上置信界：`c_UCB = c̄ + t(0.95, n−1)·s/√n`。
- **门禁规则（帕累托改善的可操作定义）**：`q_LCB(新) ≥ q_obs(旧)`（质量不降）**且**（`c_UCB(新) ≤ c_obs(旧)` 或 `q_LCB(新) − q_obs(旧) ≥ Δ`，Δ = 1/15 = 一个 cell）。一维不降、另一维不升 = 不上线。
- **历史数据量**：n = 15 时 4/5 与 5/5 的 LCB 分不开（0.63 vs 0.55，区间重叠）；n = 60 时 q̂=1.0 的 LCB = 0.95、q̂=0.8 的 LCB ≈ 0.715，可分。**结论：帕累托门禁要求 ≥ 60 campaign 的回归包** = 5 方程 × 3 B 档 × 4 seeds。数据源现成：`results/devset-run.json` + 每 campaign 的 `campaign_root` ledger；`devset_run.py` 加 seed 维即可，判定脚本读 JSON 自动判（玩法 §2）。

## 5. 不变量合规自查

| 不变量 | 落点 |
|---|---|
| Single Authoritative Ledger | L1 库是 create-only 文件 + provenance 回指 origin ledger（沿用 `export()`/`origin_status()` 机制），不建第二本账；L2 不写新事件类型，路由信息进现有 DECISION/JUMP 字段；20000 上限下增量 ≤ 12 条/campaign。 |
| Task Truth ≠ Scientific Support | 算子入库与先验排序都不构成支持；唯一资格判据仍是 oracle triple（holdout + mutant + witness），先验只排序不准入。 |
| Fail-Closed | 未知 domain_signature 桶 → 空先验不路由；契约任一不过 → 不入库；agent token 不可用 → 不唤醒；解释器遇到白名单外节点 → parse 期拒绝；runner 失败 → `TOOL_REJECTED` 照常记账（`rds_compass_rsi.py:456-462`），证据增长才重试。 |
| per-input 安全 bound | 向量化方案保留 per-input 独立 step counter + 单输入失败只丢单输入；影子模式逐字节等价 + 死循环回归测试是切换前提（b653810 的教训写进验收）。 |
| 预算 cap 不扩 | LOW_MARGINAL_EIG 与 basin 共享 `escape.max_jumps`；STEP_LIMIT/RUNNER_SECONDS/MAX_POOL 一个数不动。 |

## 6. 实施顺序（每刀独立可回滚）

1. **L1-a（离线）**：反统一脚本 + MDL 判据 + 契约生成；产出 v2 library records。风险最低，不动在线路径。
2. **L1-b（验收）**：4.1 的 15-cell 对照；过了才继续。
3. **L2-a**：decide() 的 `LOW_MARGINAL_EIG` 路由——触发点 A（`rows >= 2` 且 ranked 为空）+ **`rows == 1` 入口放宽**（§3.5）。改两个分支 + 一个 trigger 字段。
4. **L2-b（验收）**：4.2 口径，60-campaign 回归包过帕累托门禁。
5. **L1-c**：AST 解释器影子模式 → 校准 step 量纲 → 切换 + 死循环回归（等价口径见 §2.4 表）。
6. **L2-c**：τ 软触发 + Beta 后验排序 + 先验灌入 synthesize 的 grammar 权重（依赖 L1 库统计积累）。

每刀带最小反向测试：关掉新逻辑，旧行为逐字节原样（玩法 §4）。

**依赖关系（硬）：** 2 的门槛不过不许进 3；3 的任何一条不满足时必须 fall through 到现状，不许出现「路由条件 eval 出错就默认路由」的路径。每刀单独 commit，验收不过单独 revert，不混批。
