# 工作流改版指南

工作流服务于**一人即舰队**的科研节奏：替研究者扛掉杂事与跨会话失忆，不让人伺候流程。本仓库不做定时或无人值守自动优化，`scripts/doctor.py --retro` 仅作手动只读体检。

## 三条核心准绳

1. **三种模式与防混淆**：`probe`（零配置快验）/ `paper`（单篇短任务，零胶水脚本）/ `program`（长远研究树）。通用 4 条底线留在这里，领域禁令留各项目 `GOAL.md` 或 `.agents/brief.json`。
2. **讨论清再开跑，禁实验挂账**：实验卡开跑前讨论清假说、基线与证伪线，不靠“盲试挂账”碰运气；`% gate-sorry` 与 `TBD` 仅用于进行中的论文草稿待补数字，且在 `--no-sorry` 定稿时清零。
3. **先看真摩擦，先做减法**：改前对照真实报错或 `doctor.py --retro`；优先删旧规则、修误报或改配置，不轻易增脚本。保持 `AGENTS.md <= 60` 行、`SKILL.md <= 80` 行，单次只做小步增量（动核心原则与触发范围须经用户拍板），机械门禁配正反例单测，改完必过四道验收。

## 改前四问（自检提示词）

```text
1. 解决哪条已经真实出现的摩擦或失忆风险？
2. 能否靠删旧规则、修误报或改配置解决，而不增复杂度？
3. 这次改哪几处？有没有把领域禁令或实验挂账漏洞混进通用规则？
4. 改完后用哪条真实口语、草稿或测试确认生效？
```
